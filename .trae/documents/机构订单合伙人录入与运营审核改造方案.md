# 机构订单「合伙人录入 → 运营审核」流程改造方案

## 1. 目标与范围

把机构订单的创建主体从运营改为合伙人，形成闭环：

1. 合伙人在「我的订单 · 机构订单」中录入机构名称、合同编号、合同金额、约定比例、服务起始日、服务周期，并上传 1-3 张合同图片；**不填写已发放金额**。
2. 数据进入「待审核」状态，运营端「订单管理 · 机构订单」看到待审核队列，查看合同图片与分期预览后执行「通过」或「驳回」。
3. 审核通过后系统自动生成机构订单，按合同周期逐月分期解冻（服务月结束 +7 天），沿用现有佣金/结算体系；驳回需填写原因并回显给合伙人。
4. 两端通过 `localStorage` 联动，刷新后数据保留，形成可演示的完整闭环。

范围：仅修改根目录 [index.html](../../index.html) 内嵌的 `doc-partner`（合伙人端）与 `doc-ops`（运营端）两段 HTML 字符串，不改 `Demo/` 下其他文件，不引入外部库、不改变整体视觉风格。图标继续使用现有 lucide 路径体系（`renderIcons()` / 内联 lucide SVG）。

### 1.1 流程总览

```
合伙人端「我的订单 · 机构订单」
  └─ 录入机构订单（机构/合同号/金额/比例/起止周期/合同图片 1-3 张，无已发放金额）
        └─ 写入 localStorage（status=PENDING）
              └─ 运营端「订单管理 · 机构订单 · 待审核」
                    ├─ 驳回（必填原因）→ status=REJECTED → 合伙人端显示原因，可重新提交
                    └─ 通过 → status=APPROVED
                          └─ 自动生成机构订单（paid_out=0）
                                ├─ 按月分期（服务月结束 +7 天解冻）
                                ├─ 进入现有佣金/结算体系（不生成「录入时已发放」记录）
                                └─ 合伙人端订单明细同步出现（hydratePartnerOrgOrders）
```

关键边界：合伙人提交 ≠ 直接产生佣金；只有运营「通过」后才建单并计算分期。

> 注意：两段文档是两个独立的 `<script type="application/json">` 字符串，内部引号为字面 `\"`、闭合标签为字面 `<\/...>`、换行为字面 `\r\n`。修改时必须用 Python 脚本以 raw string 精确匹配（参考历史做法），禁止按行号编辑。

## 2. 现状分析

### 2.1 合伙人端（`doc-partner`，index.html 第 9 行 JSON）

- 页面路由函数 `route()`，页面 `pComm()`（我的订单），当前只有两个 tab：`S.tab = 'flow'`（订单明细） / `'settle'`（结算记录）。
- 数据为模块级静态数组：`var ORDERS = [...]`、`var SETTLE = [...]`，佣金由 `calcOrder()` / `getSum()` 实时计算。
- 已有弹窗范式：`showUnappliedModal()` 使用 `fixed inset-0 ...` 覆盖层 + `$('id').remove()`；`toast(msg)` 为全局提示。
- 当前 `pComm` 中没有任何机构订单录入入口，也没有合同上传能力。

### 2.2 运营端（`doc-ops`，index.html 第 10 行 JSON）

- 订单页 `renderOrdersView()`，子 tab `orderSubTab = 'user' | 'org'`。
- 机构 tab 顶部 `headerBtn` 目前是「＋ 录入机构订单」，调用 `openOrgEntryDrawer()`。
- 录入抽屉及提交逻辑：`openOrgEntryDrawer()` / `onOrgPartnerChange()` / `readOrgForm()` / `refreshOrgPreview()` / `confirmOrgEntry()`。表单包含「已发放金额（元）」并会生成 `IMPORT-*` 结算记录。
- 可复用的分期计算：`computeOrgPreview(f)`（`f = { amount, rate, start, months, paid }`），返回 `{ ok, msg, lines, total, unlockedSum }`；`GLOBAL_CONFIG.unfreeze_days` 控制解冻偏移。
- 机构订单写入结构参考（`confirmOrgEntry`）：
  ```js
  p.orders.unshift({ id, customer_phone:'', org_name, contract_no, kind:'ORG',
    product:'机构版年度合同（线下签约）', pay_amount, rate, points: r.total,
    status:'ORG', unfreeze_at:'按月分期', created_at, start, months,
    paid_out: f.paid, remark, is_upgrade:false, is_cool:false });
  ```
- 页面启动流程：数据种子末尾调用 `recalcAll()`，`window.onload → initRouter()`；需在 `recalcAll()` 之前补写「已通过申请 → 订单」的水合逻辑。
- 现有状态徽章/表格/抽屉样式：`badge badge-success / badge-danger / badge-neutral`、`official-table`、`content-card`、`drawer-mask show` / `drawer-panel` / `drawer-header` / `drawer-body` / `drawer-footer`、`modal-mask show` / `modal-dialog`。

## 3. 设计决策（已与用户确认）

| 决策点 | 结论 |
| --- | --- |
| 两端联动 | 使用 `localStorage` 共享申请数据，运营审核结果回写，合伙人端刷新可见 |
| 审核通过后佣金 | 立即生成机构订单，按合同周期逐月分期解冻（复用 `computeOrgPreview`） |
| 合同图片 | 最多 3 张、必传；前端压缩后以 dataURL 存储 |
| 已发放金额 | 合伙人表单不展示；审核通过生成的订单 `paid_out` 固定为 `0`，不生成「录入时已发放」结算记录 |
| 运营录入入口 | 删除，运营只审核，不再手工创建机构订单 |

## 4. 共享数据契约（两端各实现一份，key 相同）

- Key：`ll_s1_org_requests_v1`
- 值：JSON 数组，按 `created_at` 倒序。
- 单条结构：

```js
{
  id: 'ORGREQ-20261106-001',
  partner_id: 'PT-8866',
  partner_name: '李维国',
  partner_phone: '13700001111',
  org: '中国科学技术大学未来技术学院',
  contract_no: 'LL-2026-1106-01',
  amount: 50000,
  rate: 15,
  start: '2026-11-10',
  months: 12,
  remark: '年度框架合同，分两批付款',
  contract_imgs: ['data:image/jpeg;base64,...', ...],   // 1-3 张
  status: 'PENDING' | 'APPROVED' | 'REJECTED',
  created_at: '2026-11-06 14:20',
  reviewed_at: '',
  reviewer: '',
  reject_reason: '',
  order_id: ''
}
```

### 4.1 种子数据（两端使用完全相同的 `seedOrgRequests()`）

1. 待审核：`PT-8866 / 李维国`，机构「中国科学技术大学未来技术学院」，合同 `LL-2026-1106-01`，金额 `50000`，比例 `15`，起始 `2026-11-10`，12 个月，备注「年度框架合同，分两批付款」，`created_at: '2026-11-06 14:20'`，2 张合同图，`PENDING`。
2. 已驳回：`PT-9902 / 韩磊`，机构「南京大学人工智能学院」，合同 `LL-2026-1029-07`，金额 `30000`，比例 `12`，起始 `2026-10-01`，6 个月，`REJECTED`，`reviewed_at: '2026-11-02 10:15'`，`reviewer: '张博文'`，`reject_reason: '合同盖章页缺失，请补充后重新提交。'`，1 张合同图。

种子图片用运行时生成的低体积占位 SVG（`makeContractImg(title, tone)` → `'data:image/svg+xml;charset=utf-8,' + encodeURIComponent(svg)`，白色合同页 + 标题 + 红色印章圆），避免把大段 base64 写进源码。

### 4.2 通用助手（两端各一份，函数名一致）

- `ORG_LS_KEY`、`loadOrgReqs()`（try/catch 读取；无数据或解析失败则写入种子；`localStorage` 不可用时退回模块级内存数组 `_ORG_REQ_MEM`）、`saveOrgReqs(list)`（`setItem` 失败时保留内存并 `toast('本地存储不可用，仅本次演示生效')`）。
- 合伙人端请求归属常量：`DEMO_PT = { id:'PT-8866', name:'李维国', phone:'13700001111' }`，与运营端 `PT-8866` 对齐；合伙人列表只展示 `partner_id === 'PT-8866'` 的申请，避免出现他人的驳回记录。

## 5. 改动一：合伙人端（doc-partner）

### 5.1 新增数据与助手（`var ORDERS = [...]` 之后）

### 5.4 `showOrgEntryModal()` 录入弹窗（Tailwind，仿 `showUnappliedModal`）

- 覆盖层 `fixed inset-0 bg-slate-title/50 backdrop-blur-xs flex items-center justify-center p-4 z-50`；面板 `bg-surface-card rounded-[24px] border border-surface-border shadow-dropdown max-w-lg w-full max-h-[90vh] overflow-y-auto`。
- 标题「录入机构订单」+ 右上关闭（`x` 图标），底部「取消 / 提交审核」。
- 字段：
  1. 机构名称 `*`（`id="orgreq-name"`，placeholder「如 南京大学人工智能学院」）
  2. 合同编号 `*`（`orgreq-contract`）
  3. 合同金额（元）`*`（`orgreq-amount`，number）
  4. 约定比例（%）`*`（`orgreq-rate`，number，默认 `20`，提示“按合同约定填写，提交后由运营复核”）
  5. 服务起始日 `*`（`orgreq-start`，date，默认 `REF_DATE`）
  6. 服务周期（月）`*`（`orgreq-months`，number，默认 `12`，1-60）
  7. 合同图片 `*`（1-3 张）：虚线上传区 + `input type="file" accept="image/*" multiple`（隐藏）；选择后逐张校验/压缩/预览，缩略图右上角 `x` 删除；文案「最多 3 张，支持 JPG/PNG，单张≤5MB」。

- 图片处理 `readOrgImgs(files)`：
  - 校验 `file.type.startsWith('image/')`、`size <= 5MB`、总数 ≤ 3，超出 `toast` 提示；

  - 结果存入模块级 `orgImgs` 数组，重绘预览网格并 `renderIcons()`。
- `submitOrgEntry()`：
  - 校验必填、金额 > 0、比例 0-100、周期 1-60、`orgImgs.length >= 1`；
  - 合同编号重复校验：同 `PT-8866` 下存在 `PENDING/APPROVED` 且 `contract_no` 相同 → `toast('该合同编号已提交，请勿重复')`；
  - 生成 `id = 'ORGREQ-' + nowTime().slice(0,10).replace(/-/g,'') + '-' + String(seq).padStart(3,'0')`（seq 取当日申请数 +1）；
  - `partner_id/name/phone` 取 `DEMO_PT`，`status:'PENDING'`，`created_at: nowTime()`；
  - `saveOrgReqs([req, ...loadOrgReqs()])` → 关闭弹窗 → `toast('已提交，等待运营审核')` → `S.tab='org'; pComm();`。
- 图片放大/合同预览：`showImgLightbox(src)` 生成 `fixed inset-0 z-[60] bg-slate-title/80` 覆盖层 + 居中 `img`（`max-h-[85vh]`），点击任意处关闭。

  - 其他状态：仅「关闭」。

### 6.4 审核动作

`approveOrgRequest(reqId)`：

1. 取申请与 `p = PARTNERS.find(x => x.id === r.partner_id)`；找不到则 `toast('未找到对应合伙人')`。
2. 合同编号去重：`allOrgOrders().some(x => x.o.contract_no === r.contract_no)` → `toast('该合同编号已生成订单，请勿重复')`。
3. `r = computeOrgPreview({...r, paid:0})`，不合法则 `toast(r.msg)`。
4. 生成订单（结构与原 `confirmOrgEntry` 一致，`paid_out: 0`、`remark: r.remark`）：
   `id = 'ORG-' + r.start.replace(/-/g,'') + '-' + String(allOrgOrders().length+1).padStart(3,'0')`；
   `product: '机构版年度合同（线下签约）'`、`status:'ORG'`、`unfreeze_at:'按月分期'`、`created_at: nowTime()`。
5. `p.orders.unshift(order)`；`p.flow.unshift({ time, order_id:id, type:'机构订单审核通过', points:'+¥'+fmtC(preview.total), status:'合同 '+r.contract_no+'，'+r.months+' 期分期解冻' })`；`p.logs.unshift({ time, operator:'张博文', action:'审核通过机构订单', before:'待审核', after: org+' · ¥'+formatNum(amount)+' × '+rate+'%', reason:'应分佣金 ¥'+fmtC(preview.total)+'，周期 '+months+' 个月，已发放 ¥0.00' })`。
6. 回写申请：`status='APPROVED'`、`reviewed_at=nowTime()`、`reviewer='张博文'`、`order_id=id`、`reject_reason=''`；`saveOrgReqs(...)`。
7. `recalcAll()` → `closeDrawer('drawer-org-review')` → `toast('审核通过，已生成机构订单')` → 重渲染订单页（`renderOrdersView(document.getElementById('main-view-container'))`）。

`rejectOrgRequest(reqId)`：

1. 读取 `#org-review-note` 文本；为空则 `toast('请填写驳回原因')`。

## 7. 假设与约束

- 两端文档同源，`localStorage` 可共享；若以 `file://` 直接打开导致存储不可用，退化为内存数据并在提示中说明，不影响界面演示。
- 合伙人演示账号统一映射为运营端 `PT-8866（李维国）`，申请列表不展示合伙人姓名，避免与合伙人端登录名（张伟）冲突。
- 审核通过时不再采集「已发放金额」，`paid_out` 固定 0，且不写 `LINE_SETTLED` / `IMPORT-*` 结算记录。
- 已通过申请在合伙人端通过 `hydratePartnerOrgOrders()` 映射进 `ORDERS`，因此无需后端即可展示佣金与分期；驳回申请不进入 `ORDERS`。
- 合同图片经过 canvas 压缩后再入 `localStorage`，单条约 3 张 × ≤400KB，满足 5MB 配额；超限时提示并阻止提交。
- 不修改 `Demo/` 目录、不新增外部依赖、不调整整体布局与配色。
