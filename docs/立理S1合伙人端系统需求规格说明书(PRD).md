# 第一部分 · 合伙人

## 1. 产品范围

本期建设立理 S1 合伙人端 H5/Web，承载合伙人从申请入驻到推广币核算的完整链路。

- **功能范围**：双模式登录与密码找回；申请资料提交、审核状态查看；专属推广链接、推荐码与二维码海报；客户概览、客户列表、备注与标签；推广币概览、流水与线下结算记录；个人资料查询。
- **推广币结算范围**：个人月卡、年卡、加油包（可填推荐码，结算周期同月卡），以及运营后台手工录入的机构订单（按机构订单分期规则计算）。
- **升级补差**：原订单佣金与结算不变；升级单按实付差价 × 续购比例计算推广币，填写推荐码才归属合伙人，未填写则不计算、不建立归属。
- **退款与待追回**：退款由运营后台手工登记；扣回顺序为先扣未解冻期次，再扣已解冻未结算期次，已结算打款部分计入待追回，并在后续结算中自动抵扣。
- **依赖与边界**：归因、订单与支付数据由 S1 业务端提供；退款暂未接入接口，由运营后台手工登记并同步扣减推广币；申请审核、渠道及分成比例配置、账号状态管理、机构订单录入与核销由运营后台完成。本系统仅展示推广币核算与核销结果，不承接终端交易，不执行线下实际打款。

## 2. 申请入驻与准入流程

### 2.1 申请入口与宣传页

- **页面内容**：
  - 合作权益与分成机制说明（阐述立理 S1 的科研 Agent 优势、高转化率、丰厚分成及结算流程）。
  - 入驻申请表单模块。


### 2.2 申请表单字段规范

| 字段名称      | 控件类型   | 校验规则                                                |   必填性  | 占位提示语 / 说明             |
| :-------- | :----- | :-------------------------------------------------- | :----: | :--------------------- |
| **真实姓名**  | 单行文本框  | 2-20 个字符，支持中英文                                      | **必填** | 请输入您的真实姓名              |
| **所属单位**  | 单行文本框  | 2-50 个字符                                            | **必填** | 如：清华大学某某实验室 / 某某科技公司   |
| **手机号码**  | 数字输入框  | 严格校验大陆 11 位有效手机号                                    | **必填** | 请输入接收审核通知的手机号码         |
| **短信验证码** | 验证码组合框 | 6 位纯数字，60 秒倒计时防重发                                   | **必填** | 验证码（同一手机号每日最多发送 10 次）  |
| **登录密码**  | 密码输入框  | 8-20 位，必须同时包含字母和数字；只填一次，无确认密码；默认隐藏掩码，点击右侧小眼睛图标可显示明文 | **必填** | 请输入 8-20 位包含字母与数字的登录密码 |

### 2.3 提交后即时反馈与二次访问机制

1. **提交成功**：提示「申请已成功提交！官方运营团队将尽快完成审核，请保持电话畅通。」，并保留下方【前往登录页】按钮；手机号已有记录时不重复创建，提示「该手机号已有申请记录，请登录查看状态」。
2. **再次访问**：通过登录页的密码或验证码查看申请状态；审核中或已拒绝仅可查看，不开放推广中心。同一手机号仅一条记录，提交后不可重复提交或自行修改；已拒绝不提供再次申请入口，资料由运营在后台修改，手机号不可改。

## 3. 统一登录与角色分流

### 3.1 登录页结构

登录页为合伙人与运营人员共用入口，采用 **Tab 双模式切换**，**默认选中【密码登录】Tab**。

- **页面布局要素**：
  - 顶部：立理 S1 合伙人门户品牌标识与 Slogan（不展示副标题）。
  - Tab 切换器：【密码登录】（默认激活） / 【短信登录】。
  - 主体表单项：
    - 账号输入框：label 为「手机号」，占位「请输入 11 位手机号」，不自动带入脱敏手机号；运营账号可直接在该框输入，界面不单独提供运营入口。
    - 凭证输入框：密码输入框（带明暗文切换小眼睛）或 短信验证码框（含 60 秒倒计时按钮）。
    - **【忘记密码？】**：位于密码输入框下方右侧。
    - 【登录】主操作按钮。
  - **核心申请入口保留**：登录框底部提供【申请成为立理合伙人】，点击直接跳转至申请入驻页。

### 3.2 账号类型与登录方式

| 账号类型 | 账号形态 | 密码登录 | 短信登录 | 忘记密码 |
| :--- | :--- | :--- | :--- | :--- |
| **合伙人** | 11 位大陆手机号 | 支持 | 支持 | 短信自助重置 |
| **运营** | 字母开头，4–20 位字母、数字或下划线；不绑定手机号 | 支持 | 不支持 | 联系超级管理员重置 |

1. **密码登录（默认 Tab）**：输入「合伙人手机号 / 运营账号 + 登录密码」，支持明文/密文小眼睛切换。
2. **短信登录**：输入「手机号 + 短信验证码」，仅支持合伙人手机号。运营账号在此 Tab 提交时提示「账号不支持短信登录，请使用密码登录」并自动切回密码登录 Tab，点击【获取验证码】同样拦截。
3. **错误提示**：密码登录失败统一提示「账号或密码错误」，不区分账号是否存在、密码是否错误。
4. **运营账号来源**：由运营后台创建与停用（账号管理见 12.3），不支持自助注册；不允许纯数字或手机号格式，避免与合伙人手机号混淆。
5. **密码规则**：合伙人与运营账号统一为 8–20 位且同时包含字母和数字。

### 3.3 忘记密码与重置

仅适用于合伙人手机号；运营账号不提供自助找回，输入运营账号点击【忘记密码？】时提示「运营账号请联系超级管理员重置密码」，不进入本流程。

```mermaid
flowchart TD
    A[登录页 点击【忘记密码？】] --> B[进入找回密码页]
    B --> C[输入: 手机号 + 获取短信验证码]
    C --> D{校验手机号是否属于已申请合伙人}
    D -- 否(未申请过) --> E[弹窗拦截: 该手机号尚未申请成为合伙人<br/>引导前往【申请入驻】]
    D -- 是(已有记录) --> F[验证码校验通过 -> 设置新密码 (只填一次，无确认)]
    F --> G[校验密码合规性: 8-20位含字母和数字]
    G --> H[点击【确认重置】 -> 服务端加密更新密码]
    H --> I[轻提示: 密码重置成功，请重新登录]
    I --> J[自动跳转回登录页<br/>默认选中【密码登录】Tab 供输入新密码]
```

1. **访问入口**：登录页密码输入框下方的【忘记密码？】链接。
2. **重置表单字段规范**：
   - **手机号码**：输入 11 位大陆有效手机号。
   - **短信验证码**：6 位纯数字验证码，60 秒防重发倒计时。
   - **新登录密码**：8-20 位字符，必须同时包含英文字母和数字；**只填一次，没有确认密码**；默认掩码隐藏，支持点击右侧小眼睛图标显示明文。
3. **准入与安全性校验**：
   - 申请人获取验证码或提交重置时，服务端先校验该手机号是否曾提交过合伙人申请。若不存在，直接拦截提示：“该手机号尚未申请成为立理合伙人，无法找回密码”。
   - 验证码必须与手机号严格绑定并在 5 分钟内有效，单次重置成功后立即作废。
4. **重置完成交互闭环**：
   - 重置成功后，页面弹出轻提示（Toast）：“密码重置成功，请使用新密码登录”。
   - 页面延时 1.5 秒自动重定向至登录页，默认切换至【密码登录】Tab，申请人直接输入新密码即可登录。

### 3.4 登录准入规则

用户在登录页使用「密码登录」或「短信登录」点击【登录】后，服务端进行统一凭据校验与准入判定：

1. **未填写过申请表单的合伙人手机号**：
   - **完全禁止登录**。服务端鉴权拒绝并返回特定错误码。
   - 前端弹窗友好拦截提示：
     > “该手机号尚未申请成为立理合伙人，请先提交申请。”
   - 弹窗内置快捷按钮【立即申请】，点击直接跳转至申请表单页并将该手机号自动带入表单。
2. **密码校验与防暴力破解安全策略**：
   - 密码登录模式下，账号或密码错误统一提示：「账号或密码错误」。
   - 同一账号 15 分钟内连续输错密码达到 5 次，系统自动锁定该账号密码登录 15 分钟。
   - 锁定期间界面明确提示：“密码连续错误次数过多，请 15 分钟后再试，或通过【短信登录】及【忘记密码】重置后登录”。
   - **错误计数清零机制**：锁定期间仍可正常使用【短信登录】，也可通过【忘记密码】完成重置；凡通过短信登录成功、忘记密码重置成功，或密码登录成功，历史密码错误失败计数均自动清零。
3. **已有申请记录的用户**：
   - 凭证验证通过后可查看申请状态及审核结果；处于审核中或已拒绝状态时，仅能访问申请状态页，不开放推广中心等合伙人正式功能。
   - 已拒绝的申请不可重复提交或由申请人修改；如运营侧后续将状态调整为已通过，申请人刷新状态或重新登录后进入推广中心。
4. **已被官方冻结的合伙人**：
   - 登录时阻断提示：“您的合伙人合作权限已被暂停，如有疑问请联系官方管理员”，禁止进入系统。
5. **运营账号**：
   - 账号停用或会话失效时登录阻断：「该账号已被停用，请联系超级管理员」，已登录会话强制退出。

### 3.5 登录后角色分流

凭据校验成功后，服务端返回角色（合伙人 / 运营）：合伙人再按申请审核状态与账号状态分流；运营人员直接进入运营工作台。审核中和已拒绝用户只获得申请状态查询权限；只有审核通过且账号正常的合伙人可以进入推广中心及各业务功能：

| 申请审核状态               |           是否可见正式功能界面           | 登录后呈现视图与操作权限                                                                                                                                      |
| :------------------- | :----------------------------: | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| **审核中**(`PENDING`)   | **完全不可见**(无推广物料/无海报/无客户列表/无账本) | **【审核状态页】**：- 展示申请人真实提交资料：申请姓名、所属机构、手机号码、提交时间。- 进度提示：“您的立理合伙人申请正在审核中，官方团队将尽快完成审核，请保持电话畅通并耐心等待。”（不写具体天数）。- 页面仅提供【刷新状态】与【退出登录】操作，导航栏完全隐藏/锁定。        |
| **已拒绝**(`REJECTED`)  | **完全不可见**(无推广物料/无海报/无客户列表/无账本) | **【审核结果页】**：- 展示申请人真实提交资料：申请姓名、所属机构、手机号码、提交时间，以及当前审核状态。- 仅提供【刷新状态】与【退出登录】操作，不提供修改资料或再次申请入口。- 如运营侧将申请状态改为 `APPROVED`，申请人刷新状态或重新登录后直接进入推广中心。 |
| **已冻结**(`FROZEN`)    | **完全不可见**(无推广物料/无海报/无客户列表/无账本) | **登录阻断**：登录或刷新时提示“您的合伙人合作权限已被暂停，如有疑问请联系官方管理员”，不渲染任何业务页面；已登录会话强制退出登录。 |

**运营角色分流**：运营账号登录成功后进入运营工作台，按角色（超级管理员 / 审核 / 财务）展示对应菜单；无合伙人前台权限，越权访问合伙人页面返回 403；账号停用或会话失效时强制退出。

## 4. 推广物料与获客中心

推广中心是合伙人开展业务的核心工具箱，。

### 4.0 页面结构

推广中心页面由「三张概览卡 + 一整行推广海报卡」组成：

1. **我的专属推荐码**：4 位数字大字展示，底部提供【复制推荐码】，右下角显示当前账号生效的「首购 X% / 续购 Y%」（读取运营为该合伙人配置的比例，比例调整后实时更新，不在前端写死）。
2. **专属推广链接**：短链文本单行截断展示，底部提供【复制链接】，右下角显示「长期有效」状态。
3. **累计收益（推广币）**：展示净累计总推广币（数值后带「推广币」单位），底部提供【账本明细】（跳转推广币页），右下角显示「按月核算」。
4. **官方专属推广海报**：横跨整行的独立卡片，左侧海报预览，底部提供【复制短链】【保存海报图片】与使用提示。


### 4.1 专属推广链接

### 4.2.1 推荐码归因与 7 天带入规则

**基本原则**：客户关系可重叠、订单业绩唯一归属。客户来源可多元，合伙人跟进可重叠，订单归属必须唯一；销售分成以订单归属为准，不以客户绑定关系作为永久分成依据。

| 场景 | 系统行为 |
| :--- | :--- |
| 链接首次注册 | 用户通过合伙人专属链接**首次注册**账号，建立客户绑定并进入该合伙人客户列表，绑定长期保留；自注册成功起 **7 天内**下单，系统自动带入该合伙人推荐码，订单归属该合伙人 |
| 已注册用户再次访问 | 通过其他合伙人链接再次访问或登录，**不建立新绑定、不改变客户来源** |
| 主动填写推荐码 | 支付前填写有效推荐码，该单归属该推荐码对应合伙人，**优先于**客户绑定关系与 7 天自动带入 |
| 超过 7 天 | 客户绑定保留，但不再自动带入；下单需主动填写推荐码才产生归属 |
| 未填写且无法自动带入 | 未通过专属链接注册、已超 7 天且未填码、或已注册用户仅经其他合伙人链接再次访问且无自动填码规则，订单**不归属任何合伙人** |
| 支付后锁定 | 支付成功即锁定归属，不可补填或修改；支付前允许多次修改，以最终有效推荐码为准 |

- **客户列表进入条件**（满足任一即可）：① 通过该合伙人专属链接首次注册；② 使用该合伙人推荐码成功产生付费订单。
- **客户记录保留**：满足条件后长期保留，不因客户后续通过其他合伙人下单而移除；同一客户可同时出现在多个合伙人的客户列表，但同一订单只归属一位合伙人。重复出现不重复计算订单与业绩。
- **来源与成交记录分离**：客户来源绑定记录与推荐码成交记录分别留存，不因订单归属变化而覆盖或删除。
- **业绩认定时间**：以订单**支付成功时间**认定业绩；支付成功前允许多次修改推荐码，支付成功后锁定，不可补填或追溯更改。
- **推广奖励**：用户首次成功填写有效推荐码，用户额外获得 2000 积分，具体发放金额待定。
- **退款**：退款或支付失败的订单不计入业绩，已产生的推广币按退款规则冲回。
- **风控**：同一用户重复注册、重复获取推荐码奖励等行为，按平台账号风控规则处理。

**示例**：客户 C 首次通过 A 的专属链接注册，进入 A 的客户列表；注册后 7 天内直接下单，系统自动带入 A 的推荐码，订单归 A。期间 C 主动填写 B 的推荐码下单，该单归 B，C 同时进入 B 的客户列表，A 处的客户记录保留。注册满 7 天后未填写推荐码下单，该单无销售归属。

> 完整业务口径（含全场景对照表）以《立理 S1 销售分销体系归属规则》为准，本节为其在合伙人端需求中的落地描述。

## 6. 推广币与账务中心

### 6.1 推广币属性合规隔离原则

> \[!IMPORTANT]
> **合规红线**：
>
> 1. 合伙人端界面**全站严禁出现“1推广币=1元”、“可兑换现金X元”、“现金钱包”等字样**，规避金融监管与无牌支付风险。
> 2. 推广币作为合伙人推广贡献度的统一计量单位。具体的结算政策由官方运营在入驻协议或线下沟通中约定。

> \[!NOTE]
> **术语映射**：运营后台的「佣金」对应合伙人端「推广币」；「累计总金额」对应「总推广币（净收益）」；机构订单的「已发放」指录入前已线下发放的推广币。

### 6.2 核心指标看板

看板由四张核心指标卡和一条待追回提示条组成（待追回为 0 时不展示提示条）：

```
+---------------------------------------------------------------------------------+
|     总推广币              可结算推广币            冻结推广币            已结算推广币       |
|     12,680                 4,000                3,680                5,000      |
+---------------------------------------------------------------------------------+
```

1. **总推广币**：自合伙人入驻以来的**净累计总推广币**。
   - **计算口径**：$\text{总推广币} = \text{累计获得推广币} - \text{退款扣除推广币} = \text{可结算推广币} + \text{冻结推广币} + \text{已结算推广币} - \text{待追回金额}$
   - **业务特征**：总推广币代表合伙人净累计推广成果，**不会因为线下结算打款核销而减少**；发生退款扣除时，总推广币相应净减少。
   - **卡片表现**：卡片标题为「总推广币 (净收益)」；右下角提供小 `i` 图标，悬停或点击展示口径说明（公式、待追回定义与抵扣规则），卡片正文不直接展示公式。
2. **可结算推广币**：已完全度过防退款观察期（套餐周期结束 + T+N 天，N 默认 7 天、可在系统设置中配置）、目前可供官方财务进行线下打款核销的推广币余额。
3. **冻结推广币**：尚处于防退款观察期内的推广币。此部分推广币暂时不可用于结算，若遇退款将直接扣除。
   - **卡片表现**：卡片底部附注「履约周期保护中」与「待退款保护期后解冻」。
4. **已结算推广币**：官方财务已在线下完成实际打款并已在后台核销同步的累计历史推广币数额。该金额不因后续退款而冲销，退款无法扣回的部分通过「待追回」抵消。
5. **待追回金额**：退款发生在已结算打款之后，且未解冻期次与可结算余额不足以抵扣时形成的欠款（形成与抵扣规则见 10.4）。正常为 0；大于 0 时，在页面顶部展示红色提示条「存在退款待追回 ¥X，将在后续结算中自动抵扣」，并作为总推广币的扣减项。



### 6.3 推广币发放与解冻规则（月卡 / 年卡 / 加油包 / 机构订单）

推广币生命周期为三步：**产生（发放）→ 冻结（防退款观察）→ 解冻（进入可结算）**。推广币产生后一律先计入「冻结推广币」，只有到达解冻日才转入「可结算推广币」。

#### 6.3.1 发放（产生）时点

- 终端用户**支付成功**即产生推广币，金额 = 订单实付 × **该单适用分成比例**，由服务端四舍五入**保留 2 位小数（精确到分）**，全部推广币数值（订单总额、分期金额、账户汇总、流水与结算）统一按两位小数展示；订单卡片上的「本单有效推广币」在未退款时等于该订单产生的总推广币，发生退款后取退款后净值，卡片「记账时间」为支付成功时刻（机构订单为服务起始日）。
- **首购与续购界定**：首购指该客户在立理 S1 平台的**首笔成功付费订单**，适用首购比例；该客户的其余订单（复购、续费、升级补差）均适用续购比例。比例在订单支付成功时锁定，不随合伙人后续比例调整追溯变化。
- **机构订单**：不经过线上支付，以运营录入的**服务起始日**作为分期与解冻基准；分成比例默认取归属合伙人的续购比例，可按合同调整并在录入时锁定。
- 支付时点同时作为分期解冻日的计算基准（下文以「支付成功日」表述；机构订单以「服务起始日」表述）。

#### 6.3.2 月卡 / 加油包：一期制，整单一次性解冻

> 加油包下单同样支持填写推荐码，推广币结算周期与月卡一致，按本节规则执行。

| 项目 | 规则 |
| :--- | :--- |
| 发放方式 | 支付成功时一次性产生全额推广币，不分期 |
| 期数 | 1 期 |
| 解冻日 | **支付成功日 + 1 个月 + N 天**（即月卡服务期结束后再叠加 T+N 天防退款观察期，N 默认 7 天） |
| 状态流转 | 期次：未到解冻日 `冻结中` → 解冻日当天（含）起 `可结算`；订单级状态按 6.4 节规则展示 |
| 示例 | 月卡实付 ¥369.00 × 30% = 110.70 → 产生 `110.70` 推广币；支付日 2026-11-03 → 解冻日 **2026-12-10**，当日 110.70 推广币全部转入可结算 |

#### 6.3.3 年卡：12 期分期，逐月解冻

| 项目 | 规则 |
| :--- | :--- |
| 发放方式 | 支付成功时一次性产生订单总推广币，再按 12 期拆分展示与解冻 |
| 期数 | 12 期 |
| 分期金额 | 按「分」均分，保留 2 位小数：前 11 期 = `round(总额 / 12)`（四舍五入到分），第 12 期 = 总额 − 前 11 期之和（尾差归入最后一期，保证 12 期合计等于总推广币） |
| 解冻日 | 第 k 期解冻日 = **支付成功日 + k 个月 + N 天**（k = 1…12），即每个服务月结束后再叠加 T+N 天 |
| 状态流转 | 各期独立：未到解冻日 `冻结中` → 解冻日当天（含）起 `可结算`；订单级状态按 6.4 节规则汇总展示 |
| 示例 | 年卡实付 ¥2,999.00 × 30% = 899.70 → 总推广币 `899.70`；每期 899.70 ÷ 12 = 74.975 → 前 11 期各 `74.98`，第 12 期 `899.70 − 74.98×11 = 74.92`；支付日 2026-11-03 → 第 1 期 2026-12-10 解冻 74.98、第 2 期 2027-01-10 解冻 74.98……第 12 期 2027-11-10 解冻 74.92 |

- **期次展示**：订单卡内以 12 段色块进度条呈现（绿色=可结算、蓝色=已结算、黄色=冻结中、红色=退款扣除/待追回），并附「已解冻 n/12 期 · 下期 YYYY-MM-DD 解冻 +X」摘要；点击【查看分期明细】逐期展开「第 n 期 / 解冻日 / +X / 状态」。
- **解冻判定口径**：解冻日当天（含）即视为已解冻，由服务端按自然日计算（`加月 + N 天`，遇月末按目标月末自然截断）。

#### 6.3.4 机构订单：N 期分期

| 项目 | 规则 |
| :--- | :--- |
| 适用场景 | 运营后台手工录入的机构订单（线下合同），不经过 S1 线上支付 |
| 发放方式 | 录入时一次性产生应分推广币，再按服务周期（月）拆分为 M 期 |
| 期数 | M = 服务周期月数（1~60），默认 12 |
| 分成比例 | 默认带出归属合伙人的续购比例，可按合同调整（0~100 整数），录入后锁定，仅作用于该单 |
| 分期金额 | 应分推广币 = 合同金额 × 分成比例；前 M−1 期 = round2(总额 / M)，第 M 期取尾差，保证 M 期合计等于总额 |
| 解冻日 | 第 k 期解冻日 = **服务起始日 + k 个月 + N 天**（N 为防退款观察期，默认 7 天） |
| 归属 | 由运营在录入时指定合伙人，不依赖推荐码，也不适用 7 天带入规则 |
| 已发放金额 | 录入前已线下发放的部分，不得超过应分推广币总额及截至录入日已解冻金额；按期次从前往后抵扣，并生成一条「录入时已发放」结算记录（不可撤销）；合伙人端在结算记录中展示 |
| 退款 | 按 10.4 规则扣回，退款上限为合同金额或合同约定金额 |
| 展示 | 订单号 `ORG-YYYYMMDD-三位序号`；客户位置展示机构名称；其余按 6.4 节订单卡展示 |

- **示例**：机构合同金额 ¥12,000，续购比例 20%，应分推广币 2,400.00，分 12 期，每期 200.00；服务起始日 2026-11-01，则第 1 期解冻日为 2026-12-08（+1 个月 +7 天），第 12 期解冻日为 2027-11-08。

#### 6.3.5 退款后的展示表现

> 退款扣回的计算规则（应扣回金额、扣回顺序、待追回形成与结算抵扣）统一见 **10.4 退款登记与扣回规则**，本节仅描述合伙人端的展示表现。

- **期次被扣空**：该期标记 `退款扣除`，金额显示 `−X`（并附「（原 X）」）。
- **部分退款**：**不新增订单状态**，订单状态仍按 6.4 节资金状态（冻结中 / 可结算 / 已结算）展示；卡片展示红色退款信息行「退款 N 笔，累计 ¥X（最近日期）· 累计扣除 −X 推广币」，多次退款合并为一条；右侧「本单有效推广币」取退款后净值，并以删除线展示原总推广币。
- **全额退款**：订单状态为 `已退款`；尚未解冻 / 未结算的期次标记 `退款扣除`；已结算打款期次保持 `已结算`，无法扣回的部分计入 `待追回`。
- **撤销全部退款登记**：推广币金额、期次状态与待追回金额同步回滚，退款信息行消失。

#### 6.3.6 升级补差订单

1. **订单形式**：升级由两笔独立支付订单构成——原订单 A 与升级单 B，B 的实付金额为套餐差价；数据层在 B 上记录原订单号，用于对账与追溯。
2. **佣金计算**：原订单 A 的推广币、解冻与结算不因升级变更；升级单 B 按「实付差价 × 续购比例」产生推广币，解冻规则按新套餐类型执行；B 未填写推荐码的不产生推广币、不建立归属。
3. **退款处理**：B 的退款上限为其实际支付差价；退「升级后套餐全款」时，分别对 A、B 各登记一次退款，扣回规则见 10.4；支付渠道超期无法原路退回的，走线下退款并手工核销。
4. **展示表现**：B 的商品名称括号内标注 `升级补差`，订单状态仍按 6.4 节资金状态展示；A 保持普通订单展示。
5. **示例**：客户 2026-10-12 购入 Pro 年卡 ¥2,999，首购 30% 产生佣金 ¥899.70（12 期）；10-25 升级 Max 年卡 ¥3,999，补差 ¥1,000，升级单按续购 20% 产生佣金 ¥200（12 期）。原单 ¥899.70 的佣金与解冻进度不变；若客户要求退升级后套餐全款，则分别退原单 ¥2,999 与升级单 ¥1,000，两单各自按 10.4 规则独立扣回，未解冻期次直接扣回、已解冻未结算部分从可结算余额抵扣、已结算打款部分计入待追回。

#### 6.3.7 解冻后如何进入结算

- 解冻只做「冻结 → 可结算」的账户级转换，不按订单单独打款；
- 官方财务按月对账户整体核销线下打款（金额从可结算转入已结算），核销记录见 6.5 节；
- 存在待追回时，本次实结 = 明细合计 − 待追回扣减，本次实结按 10.4 规则扣减，结算记录展示见 6.5 节；
- 订单维度仅承担「推广币产生 + 分期解冻 + 退款扣回」核算，不体现打款动作。



### 6.4 账单流水列表（明细）

流水列表以 **订单卡片** 形式展示，页面提供两个 Tab：

- **订单明细**（默认选中）：按订单展示推广币明细；年卡、机构订单按月分期发放。
- **结算记录**：展示财务线下对公转账及机构订单录入时已发放的结算记录（详见 6.5 节）。

单条订单卡包含以下要素：

| 要素              | 示例展示值                                 | 说明与取整规则                                 |
| :-------------- | :------------------------------------ | :-------------------------------------- |
| **商品名称 + 状态徽标** | Pro 月卡（续购） `冻结中`                      | 个人套餐名称或机构订单合同商品名；括号内标注该单类型（首购 / 续购 / 升级补差 / 机构订单）+ 订单状态徽标 |
| **订单实付**        | ¥369.00                               | 终端用户的实际支付金额（折算基准）；机构订单为合同金额                       |
| **分成比例**        | 30%（首购）/ 20%（续购）                     | 该订单适用的分成比例：客户平台首笔付费取首购比例，其余取续购比例；机构订单为录入时锁定的合同比例 |
| **订单号 · 记账时间**  | `ORD2026110300921 · 2026-11-03 14:20` | 个人订单为 `ORD...`；机构订单为 `ORG-YYYYMMDD-三位序号`；时间为支付成功时间或机构订单服务起始日               |
| **客户 / 机构**     | `138****4501` / `华东理工大学...`           | 个人订单展示脱敏手机号，中间 4 位隐藏；机构订单展示机构名称                     |
| **退款信息行**       | 退款 1 笔 ¥124.96（2026-11-06）· 扣除 −37.49 推广币 | 仅发生退款时展示，红色文案；多次退款合并为一条；全额退款标注「全额退款」；撤销后退款行消失 |
| **本单有效推广币**      | `73.21`                              | 卡片右侧展示；年卡 / 机构订单附注「按分期期数发放」；发生退款时展示原推广币删除线  |
| **四宫格拆分**       | 可结算 / 冻结中 / 已结算 / 退款扣除                | 四段拆分；四段合计等于本单原总推广币；待追回不单独占段，以卡片底部提示展示；为 0 时灰色显示，退款扣除以负数展示 |

**订单状态徽标枚举**：

| 状态 | 定义 |
| :--- | :--- |
| `冻结中` | 仍有未解冻金额，且当前没有可结算金额（含部分期次已结算的情况） |
| `可结算` | 当前存在已解冻但未结算金额 |
| `已结算` | 无冻结、无可结算，本单有效推广币已全部结算（可能存在待追回） |
| `已退款` | 已登记全额退款（退款金额等于实付），退款后本单有效推广币为 0 |

判定优先级：`已退款` > `可结算` > `冻结中` > `已结算`。订单状态为合伙人端资金状态，与运营后台的订单支付状态（已支付 / 已退款）不是同一维度。`已结算` 订单仍可能存在待追回，需同时展示待追回提示。

- **状态流转**：`冻结中` → 到达解冻日 → `可结算` → 结算核销 → `已结算`；`冻结中` / `可结算` 被退款扣空 → `退款扣除`；`已结算` 遇退款且无法扣回 → `待追回` → 后续结算抵扣完成 → `已结算`；全额退款 → `已退款`。
- **全额退款与已结算并存**：`已退款` 订单若存在已打款期次，这些期次仍保持 `已结算`，无法扣回部分计入 `待追回`，不会把已打款金额从已结算中抹掉。

- **不再展示**「部分退款」「已全额退款」「分期解冻中 n/N」「已全部解冻」等订单级徽标；退款属性只在退款信息行体现，分期进度只在进度条与摘要中体现。
- **年卡 / 机构订单分期展示**：卡片内提供分期进度条（绿色=可结算、蓝色=已结算、黄色=冻结中、红色=退款扣除/待追回），并附「已解冻 n/N 期 · 下期 YYYY-MM-DD 解冻 +X」摘要与【查看分期明细】/【收起分期明细】按钮。
  - 展开后逐期展示：`第 n 期`、`解冻日 YYYY-MM-DD`、`+X`（发生退款时显示 `−X`）、`退款扣除`（附「（原 X）」）、`待追回 X`、状态徽标（`冻结中 / 可结算 / 已结算 / 退款扣除 / 待追回`）。
  - 部分扣减不新增状态：该期保留原状态，金额显示剩余值并标注「已扣 X」。
- **待追回提示**：本单存在待追回时，卡片底部展示红色说明「本单待追回 ¥X，将在后续结算中自动抵扣」；待追回为 0 时不展示。
- **卡片区底部说明文案**：月卡 / 加油包推广币在服务期结束 +N 天后解冻；年卡与机构订单按服务周期逐月分期，每期在对应服务月结束 +N 天后解冻并进入可结算；退款从最后一期往前扣，先扣未解冻期次，再扣已解冻未结算期次，已结算打款部分计入待追回并在后续结算中自动抵扣；线下结算按账户整体核销，不拆分到单个订单。
- **取整规则说明**：系统内部计算按订单实付金额 $\times$ 该单适用分成比例后，**一律由服务端四舍五入保留两位小数（精确到分）生成并展示推广币**，整数金额同样展示两位小数：
  - *示例 1*：实付 ¥369.00 $\times$ 30% = 110.70 $\to$ 显示 `110.70`（原 `+110.70 推广币`）。
  - *示例 2*：实付 ¥2,999.00 $\times$ 30% = 899.70 $\to$ 显示 `899.70`。
  - *示例 3*：实付 ¥99.00 $\times$ 30% = 29.70 $\to$ 显示 `29.70`。
- **退款流水展示**：退款流水行状态统一为 **“退款扣除”**，对应推广币显式 **以负数呈现**（例如：原实付 ¥299 的订单发生退款，展示为 `-89.70 推广币`）。

### 6.5 线下打款与已发放记录

展示两类结算记录：运营线下打款核销记录，以及机构订单录入时已线下发放的记录。每条记录为一张卡片，字段如下：

- **结算批次号**：如 `SETTLE-202610-008`；机构订单「录入时已发放」记录使用运营生成的对应结算单号。
- **结算状态**：线下结算记录为「已结算」，机构订单「录入时已发放」记录为「已发放」；均以绿色徽标展示。
- **结算来源**：`线下结算` / `录入时已发放`（机构订单）。
- **结算核准时间**：后台运营点击核实确认完成的时间（`YYYY-MM-DD HH:mm`）。
- **明细合计**：本次核销或已发放的推广币总额，以负数展示（如 `-2,000.00 推广币`），统一保留两位小数。
- **扣减待追回**：本次从实结中扣减的待追回金额，以正数展示；无待追回时为 `0.00`。
- **本次实结**：`|明细合计| − 扣减待追回`，以负数展示（如 `-1,925.02 推广币`）；「录入时已发放」记录即为该笔已发放金额。

补充说明：

- 记录卡片不展示打款凭证号 / 打款附言，也不提供任何操作按钮。
- 页面右上角说明文案为「展示财务线下对公转账及机构订单录入时已发放的结算记录」。
- 「录入时已发放」记录不可撤销，仅用于展示机构订单录入前已线下发放的推广币。
- 扣减待追回不超过明细合计；本次未扣完的待追回结转下次结算，页面继续展示待追回提示。

## 7. 我的资料页面

“我的资料”为合伙人个人档案信息页面，提供清晰的入驻身份与资质核对视图：

### 7.1 页面展示要素

页面顶部为合伙人身份摘要卡：左侧为姓名首字圆形头像 + 真实姓名 + 所属单位，右侧提供【退出登录】按钮。

下方以只读键值行展示申请入驻时提交的真实资料（卡片不设标题），字段及顺序如下：

- **真实姓名**：申请填写的真实姓名（如“李某某”）。
- **所属单位**：申请填写的单位/高校实验室名称。
- **手机号码**：绑定登录的手机号（**完整展示**，如 `13812345678`）。
- **微信号**：申请填写的联系微信号（未填则显示「未填写」）。
- **申请入驻时间**：首次提交申请的时间戳（`YYYY-MM-DD HH:mm`，非审核通过时间）。
- **专属推荐码**：当前生效的 4 位推荐码（等宽字体加粗展示，如 `8866`）。
- **基准分润比例**：当前账号生效的首购 / 续购比例（如「首购 30% / 续购 20%」），读取运营配置实时展示，不在前端写死，不附加结算方式文案。

> \[!IMPORTANT]
> **安全与修改限制**：
>
> 1. 本页面**严禁展示合伙人登录密码**。
> 2. 合伙人端**不提供自主修改资料（含所属单位、收款信息）的入口**，页面也不展示资料修改规则提示文案。
> 3. 本页面**不展示渠道类型（内部 / 外部）**，避免合伙人之间比较分润比例。

| 要素   | 内容                                                                      |
| :--- | :---------------------------------------------------------------------- |
| 卡片标题 | 账号与安全密码                                                                 |

| 操作按钮 | 【修改登录密码】                                                                |
| 跳转规则 | 点击后跳转至找回密码页（流程与 3.2 节一致：手机号 + 短信验证码 + 设置新密码） |

> \[!NOTE]

# 第二部分 · 运营管理

运营后台为合伙人体系的运营与财务中枢，包含以下板块：

- **申请审核**：入驻申请的筛选、详情、通过、拒绝、重新审核
- **合伙人管理**：合伙人列表、档案详情，以及修改分成比例、冻结、解冻
- **订单管理**：用户订单、机构订单、录入机构订单、退款登记
- **结算管理**：待结算、结算历史
- **系统设置**：默认分成比例、冻结规则


## 8. 申请审核

负责合伙人入驻申请的状态流转与准入建档，默认进入「待审核」列表。

### 8.1 筛选与列表

- **分段 Tab**：待审核（默认）、已通过、已拒绝、全部申请。
- **筛选条件**：关键词（申请 ID / 姓名 / 完整手机号 / 机构单位，输入即实时过滤）、审核状态（下拉与分段 Tab 联动）、申请时间区间（双月日历选择起止日期，支持「近 7 天」「本月」快捷预设、清空、取消 / 确定）。
- **列表字段**：申请人姓名、手机号、所属单位 / 学术机构、微信号、申请时间、审核状态、操作。
- **按 Tab 差异展示**：
  - 待审核：展示申请人、手机号、单位、微信号、申请时间、审核状态、操作。
  - 已通过：增加「入驻时间」（审核通过时间）与「操作人」（执行通过的运营账号）列。
  - 已拒绝：增加「拒绝时间」与「操作人」（执行拒绝的运营账号）列。
  - 全部申请：展示「操作人」列，已通过 / 已拒绝显示对应审核人，待审核行留空。
- **排序**：待审核按申请时间升序（早→晚）；已通过按入驻时间降序、已拒绝按拒绝时间降序、全部申请按申请时间降序（晚→早）。

### 8.2 审核操作

| 操作 | 说明 |
| :--- | :--- |
| 详情 | 抽屉查看并编辑申请资料（姓名、单位、微信号可修改，手机号只读） |
| 通过 | 弹窗选择渠道类型（外部 / 内部，默认外部）、填写首购与续购比例、填写专属推荐码；确认后自动在合伙人管理建档并激活账号 |
| 重新审核 | 已拒绝申请使用同一「通过」弹窗，确认后状态回转为已通过 |
| 拒绝 | 弹窗展示申请人信息，确认后直接拒绝；申请人状态页显示已拒绝 |

- **首购 / 续购比例**：各取值为 0~100 的整数（不支持小数）；按渠道类型自动带出系统默认值（内部 首购 15% / 续购 10%，外部 首购 30% / 续购 20%，可在「系统设置」中调整），仅对后续新订单生效。
- **专属推荐码**：4 位纯数字，打开通过弹窗时自动生成（生成时避开已占用的码），支持手动修改与重新生成；提交时再次校验，重复提示「该推荐码已被占用，请更换或重新生成」。


## 9. 合伙人管理

### 9.1 合伙人列表

- **筛选条件**：关键词（合伙人姓名 / 完整手机号 / 4 位推荐码 / 机构，输入即实时过滤）、渠道类型（全部渠道 / 内部渠道（员工、顾问）/ 外部渠道（高校、博主））、账号状态（全部状态 / 正常 / 已冻结）；提供「重置」按钮。
- **列表字段**：合伙人姓名、账号状态、单位、手机号、渠道、推荐码、首购 / 续购比例、总销售额、累计总金额、加入时间、操作。
- **状态展示**：账号状态以徽标展示「正常 / 已冻结」，已冻结束时可查看冻结原因；推荐码在冻结状态下附「已失效」标记。
- **总销售额口径**：该合伙人所带全部订单的实付金额合计，已扣除登记的退款金额（退款后实付净额）。
- **列表操作**：`详情`（进入合伙人档案）、`改比例`；已冻结合伙人额外提供 `解冻`。

### 9.2 合伙人档案详情

- **头部**：姓名 + 渠道徽标（内部 / 外部渠道）+ 账号状态徽标；所属单位、加入时间；右上操作区提供 `修改分成比例`、`冻结账号` / `解冻恢复`。
- **五张汇总卡**：累计总金额（扣除退款）、当前可结算金额、冻结中金额、累计已结算金额、待追回金额（异常）。各字段口径如下：

| 卡片字段 | 定义与统计口径 | 展示与使用说明 |
| :--- | :--- | :--- |
| **累计总金额（扣除退款）** | `累计获得推广币 − 退款扣除推广币`，且满足 `当前可结算金额 + 冻结中金额 + 累计已结算金额 − 待追回金额` | 与合伙人端「总推广币（净收益）」同口径；线下打款核销不会使其减少，仅退款扣除会使其净减少 |
| **当前可结算金额** | 已过防退款观察期且尚未结算的推广币合计；存在待追回时，实际可打款金额还需先扣减待追回 | 即本轮可发起结算的金额上限；已冻结合伙人不可发起结算，点击时提示先解冻 |
| **冻结中金额** | 尚未到解冻日的推广币合计（解冻日 = 服务期结束 + N 天，N 默认 7 天，可在系统设置调整） | 该部分不可结算；发生退款时优先从该部分扣回 |
| **累计已结算金额** | 已线下实际打款到账的推广币累计，按每笔结算记录的「本次实结」累计（即明细合计减去扣减待追回），含机构订单「录入时已发放」金额 | 反映已发生的打款历史，不会因退款回退；退款涉及已打款部分时转为「待追回」，在后续结算的本次实结中扣减，合伙人实际到手金额相应减少 |
| **待追回金额（异常）** | 只有客户退款时才会出现：该单已有期次打款（已结算），而「未解冻期次 + 已解冻未结算期次」的钱不足以抵扣全部应扣回的推广币，剩余扣不掉的部分即为待追回 | 未发生退款时为 0；出现后红色高亮，在下期结算打款中自动扣减，扣完恢复 0，运营需同步告知合伙人 |

> \[!NOTE]
> **待追回示例**：年卡实付 ¥2,999 × 30%，佣金 899.70，12 期每期约 74.98。客户使用 2 个月后反馈效果不佳要求全额退款：前 2 期已解冻共 149.96，其中 1 期已打款 74.98、另 1 期仍在可结算余额中可直接抵扣；未解冻的 10 期 749.74 全部扣回，仍有 74.98 无法扣回，即记入「待追回」，在下期结算打款时扣减至 0。

- **基础信息**：手机号码、专属推荐码（4 位）、当前分成比例（首购 / 续购）、微信号。
- **归属订单 Tab**：订单编号、下单客户 / 机构、商品名称（含商品标签与服务期）、订单状态（已支付 / 已退款）、订单金额、分成比例、本单佣金、下单时间、操作（`分期明细`、`退款登记`）。
- **线下结算历史 Tab**：结算单号、核销金额（本次实结，负数展示；存在待追回时同步展示「明细合计 / 扣减待追回」）、财务打款凭证号、经办人、核销时间、打款备注说明。
- **统计口径补充**：「累计已结算金额」= 线下结算记录的「本次实结」合计 + 机构订单「录入时已发放」金额（不含被抵扣的待追回部分）；「录入时已发放」仅一次性抵扣、不可撤销，不重复计入可结算。

### 9.3 账号操作规范

| 操作 | 弹窗内容 | 业务影响 |
| :--- | :--- | :--- |
| 修改分成比例 | 展示当前比例；填写新首购比例、新续购比例（0~100 的整数） | 仅对修改后新产生订单生效，历史订单不追溯重算 |
| 冻结账号 | 展示风险提示（无法登录前台、推荐码与推广链接失效、下单不再产生归属与佣金、历史可结算金额保留）；填写冻结原因（必填） | 合伙人立即无法登录前台，推荐码失效，下单不再产生归属与佣金 |
| 解冻恢复 | 二次确认 | 恢复正常状态，可正常登录、推荐码恢复生效并参与结算 |

- 冻结账号在「待结算」中不可发起结算，点击时提示先解冻。

## 10. 订单管理

订单管理承载用户订单与机构订单台账，页面以「用户订单」「机构订单」两个 Tab 切换；右上角「录入机构订单」仅在机构订单 Tab 展示。

### 10.1 用户订单

- **数据来源**：线上订单（月卡、年卡、加油包、升级补差），系统自动归集，无需人工录入。
- **筛选条件**：关键词（订单编号、客户手机号、合伙人姓名）、订单状态（全部状态 / 已支付 / 已退款）、重置按钮；输入与切换即时过滤。
- **排序**：按下单时间倒序。
- **汇总条**：订单总数、总销售金额（实付合计扣除已登记退款）、佣金合计（退款后净额），均按筛选结果统计。
- **列表字段**：订单编号、下单客户、商品名称、归属合伙人、订单状态、订单金额、分成比例、本单佣金、下单时间、操作。
- **展示规则**：
  - 商品列展示两行：主行为套餐名（Lite / Pro / Max 月卡、年卡、加油包）；次行为单笔类型标签：`首购` / `续购` / `升级补差`。
  - **升级补差**：客户在会员有效期内由低档套餐升级为高档套餐，只补付差价的新订单；该单按实付差价 × 续购比例计算推广币，原订单的佣金与结算不受影响，填写推荐码才归属合伙人。
  - 归属合伙人展示姓名 + 「内部渠道 / 外部渠道」副行。
  - 订单金额展示退款后净额（实付 − 累计退款），有退款时下方小字「已退 ¥X」。
  - 本单佣金正数显示 `+¥X`；发生退款后按退款后实付金额重算，最低为 0，直接展示重算后金额。
  - 订单状态为徽标：`已支付` / `已退款`；退款金额与扣回明细在分期明细中查看。
- **操作**：`分期明细` 抽屉展示订单金额（退款后净额与「已退」小字）、分成比例、本单佣金（退款后金额）、退款信息（退款日期、金额、原因、凭证）、可结算 / 冻结中 / 已结算三张金额卡，以及逐期「期次 / 服务期间 / 解冻日 / 金额 / 状态」；`退款登记` 入口在已退满时隐藏。

#### 退款展示规则

- **订单金额**：显示退款后净额（实付 − 累计退款），有退款时下方小字「已退 ¥X」。
- **本单佣金**：显示按退款后实付重算的金额，最低为 0。
- **退款信息**：展示退款日期、金额、原因、凭证号，并标注「部分退款 / 全额退款」。
- **期次扣减**：被扣空的期次显示「退款扣除」；部分扣减时金额显示剩余值，下方小字「已扣 ¥X」。
- **待追回**：已结算打款、无法从可结算余额抵扣的期次显示「待追回」并标注金额，累计计入合伙人待追回金额，下次结算打款时扣减。

**期次状态标签**

| 标签 | 定义 |
| :--- | :--- |
| 冻结中 | 尚未到解冻日，佣金锁定，计入冻结中金额 |
| 可结算 | 已解冻且未被结算单核销，计入可结算金额 |
| 已结算 | 已被结算单核销打款 |
| 退款扣除 | 因退款被扣空，该期佣金不再发放 |
| 待追回 | 该期已打款、退款时无法从可结算余额抵扣，形成合伙人欠款，下次结算扣减 |


### 10.2 机构订单

- **业务背景**：机构年度套餐为线下签合同，无法在线上自动打通，由运营手动录入。
- **说明条**：列表上方展示录入说明：线下签合同、按合同填写金额 / 比例 / 周期、解冻规则与年卡一致（服务月结束 +7 天），解冻明细统一在「结算管理 · 待结算」核对。
- **列表字段**：订单编号、机构名称、商品名称、合伙人、订单状态、订单金额、分成比例、本单佣金、下单时间、操作。
- **商品列**：合同商品名 + 「N 个月服务期」标签。
- **编号口径**：
  - **订单编号**：录入后自动生成 `ORG-YYYYMMDD-三位序号`（服务起始日 + 流水号），列表首列展示。
  - **合同编号**：录入时手工填写、系统查重；在「分期明细」抽屉顶部展示。
- **展示规则**：归属合伙人展示姓名 + 渠道副行；本单佣金与订单状态规则同用户订单。
- **排序**：按服务起始日倒序。
- **操作**：`分期明细`、`退款登记`（已退满的订单不提供该入口）。

### 10.3 录入机构订单

| 字段 | 必填性 | 规则说明 |
| :--- | :---: | :--- |
| 归属合伙人 | 必填 | 下拉展示「姓名 · 单位 · 渠道（续购比例）」，切换时带出该合伙人续购比例 |
| 机构名称 | 必填 | 线下签约机构全称 |
| 合同编号 | 必填 | 手工填写，提交时查重，重复提示「该合同编号已录入，请勿重复」 |
| 合同金额（元） | 必填 | 按合同实际金额 |
| 分成比例（%） | 必填 | 默认带出合伙人续购比例；0~100 的整数，可按合同调整；录入后锁定 |
| 服务起始日 | 必填 | 默认当天，决定分期与解冻基准日 |
| 服务周期（月） | 必填 | 默认 12 个月，取值 1-60；下方实时显示服务期间起止日 |
| 已发放金额（元） | 选填 | 录入前已线下发放的佣金；不得超过应分佣金总额，也不得超过截至今日已解冻金额；按期次从前往后抵扣 |
| 备注 | 选填 | 合同补充说明 |

- **分期预览**：实时展示应分佣金总额、已发放、可结算（已解冻未结算）、冻结中四张卡，及逐期明细「期次 / 服务期间 / 解冻日 / 金额 / 状态（已发放 / 可结算 / 冻结中）」。
- **已发放金额处理**：抵扣后生成一条「录入时已发放」结算记录，该记录不可撤销。
- **提交后**：生成机构订单及分期明细，写入合伙人流水；提示「机构订单已录入：应分佣金 ¥X，共 N 期」，页面自动切换至「机构订单」。



### 10.4 退款登记与扣回规则（无接口，运营手工登记）

**背景**：系统暂未接入退款接口，实际退款须由运营手工登记，合伙人佣金才会同步扣回。

**入口与范围**
- 用户订单、机构订单列表行内「退款登记」均可发起；已退满（累计退款 = 实付）的订单不再提供入口。
- 同一订单可多次登记部分退款；已登记内容不支持修改，需「撤销全部退款登记」后重新登记。
- 升级补差单的退款上限为其实付差价；需退「升级后套餐全款」时，分别对原订单与升级单各登记一次退款。

**表单字段**

| 字段 | 必填 | 规则 |
| :--- | :---: | :--- |
| 归属合伙人 | — | 只读展示「姓名 · 渠道」 |
| 订单实付 / 剩余可退 | — | 只读展示实付金额与剩余可退金额 |
| 本次退款金额（元） | 是 | ≤ 实付 − 累计退款 |
| 退款日期 | 是 | 默认为当天，≤ 当天 |
| 退款凭证号 | 否 | 财务退款流水号 / 商户退款单号 |
| 退款原因 | 是 | 文本 |

**扣回规则（全系统唯一出处）**
1. **应扣回佣金**：`应扣回 = round2(原实付 × 该单适用分成比例) − round2((原实付 − 累计退款) × 该单适用分成比例)`，round2 为四舍五入保留两位小数；全额退款时本单有效推广币归零。
2. **扣回顺序**：从最后一期往前扣：先扣**尚未解冻**的期次；不足时再扣**已解冻但未结算**的期次；已结算并已打款的部分无法扣回。
3. **待追回形成**：只有「发生退款」且「该单已有期次打款」同时成立、且上述可扣金额不足以抵扣全部应扣回金额时才会产生；无法扣回的差额计入该合伙人「待追回金额」。未发生退款、或退款仅涉及未打款期次时，待追回恒为 0。
4. **待追回抵扣**：在下次结算时从本次实结中扣减，且不超过本次明细合计；未扣完部分结转下期继续扣，直至为 0。
5. **多次退款**：同一订单多次登记时，按累计退款金额一次性重算应扣回金额，不逐笔叠加扣回。
6. **升级补差**：原订单 A 与升级单 B 各自独立按本节扣回，互不冲抵。
7. **状态口径**：不新增订单状态，仅在期次维度展示 `退款扣除` / `待追回`（期次状态枚举见 6.4 节）。

**实时预览**：展示应扣回佣金、可从冻结 / 可结算期次扣回金额、计入待追回金额、逐期扣回明细（第 N 期 −¥X）、退款后本单佣金。

**提交后联动**
- 订单：展示退款标记「部分退款 / 全额退款」，本单佣金显示退款后净额，被扣空期次显示「退款扣除」；合伙人端订单状态仍按资金状态（冻结中 / 可结算 / 已结算 / 已退款）展示。
- 合伙人：总佣金、可结算 / 冻结中 / 已结算与待追回金额同步重算。
- 留痕：写入合伙人流水「退款扣除」（退款金额、扣回额、凭证）。

**撤销**：支持撤销该订单全部退款登记，佣金、可结算金额与待追回金额同步回滚。

**计算示例（部分退款，未产生待追回）**：年卡实付 ¥2,999.00，2026-08-20 支付，分成比例 30%，总推广币 899.70，12 期（前 11 期 74.98、第 12 期 74.92），每期服务金额 249.92（第 12 期 249.88）。
- 2026-11-06 客户申请退款：第 3 期服务期（2026-10-20 ~ 2026-11-19）已使用一半，按半退；第 4 期起（2026-11-20 之后）未使用，全额退。
- 退款金额 = 第 3 期一半 124.96 + 第 4~12 期 2,249.24 = **¥2,374.20**，退款后净实付 624.80。
- 应扣回 = `2,999 × 30% − 624.80 × 30%` = 899.70 − 187.44 = **712.26**。
- 扣回顺序从最后一期往前：第 12 期 74.92、第 11~4 期各 74.98（共 599.84）全部扣空，第 3 期再扣 37.50、余 37.48 继续冻结（对应已使用的半个服务月，2026-11-27 解冻）；第 1 期已于 2026-09-27 解冻，并在 2026-10-28 结算单 `SETTLE-202610-008` 中结清（状态 `已结算`）；第 2 期 2026-10-27 解冻后进入可结算（状态 `可结算`）。因未解冻期次已足够抵扣，第 2 期未被扣减；若未解冻期次不足，则继续扣第 2 期可结算金额。
- 结果：本单有效推广币 187.44，该合伙人待追回金额为 0。

**计算示例（产生待追回）**：年卡实付 ¥2,999.00，分成比例 30%，总推广币 899.70，12 期；客户使用 2 个月后申请全额退款。前 2 期已解冻共 149.96（第 1 期已结算 74.98，第 2 期可结算 74.98），未解冻 10 期共 749.74。应扣回 899.70：先扣未解冻 749.74，再扣第 2 期可结算 74.98，仍差 74.98 无法从已打款的第 1 期扣回，计入待追回；下次结算实结 = 明细合计 − 74.98。

## 11. 结算管理

页面含「待结算」「结算历史」两个 Tab。

### 11.1 待结算

- **列表字段**：合伙人姓名、单位、手机号、渠道、账号状态、可结算金额、最早解冻日、操作。
- **状态展示**：渠道为「内部 / 外部」徽标；账号状态为「正常 / 已冻结」徽标，已冻结悬停提示「账号已冻结，请审慎核销」。
- **操作**：正常合伙人「核对并结算」；已冻结合伙人「不可结算」（禁用，悬停提示需先解冻账号）。

### 11.2 结算核对（抽屉）

- **头部**：结算核对单 · 合伙人姓名，附渠道徽标；账号冻结时增加「账号已冻结」徽标。
- **信息行**：单位 · 手机号 · 微信。
- **待追回提示**：存在待追回时置顶红色提示条，展示待追回金额与本次自动扣减金额；扣减后仍有剩余时提示剩余金额结转下次扣减。扣减口径见 10.4。
- **结算范围行**：展示「本期可结算范围：YYYY-MM-DD（含）之前解冻的佣金」，右侧「全选 / 清空」。
- **明细表**：勾选、商品名称（类型徽标 + 来源）、订单号、客户 / 机构、期次 / 服务期间、解冻日、本次可结算（已部分结算时附「已结算 ¥X（原 ¥X）」）。
- **表单**：财务打款凭证流水单号（必填，自动生成、可修改）、结算经办人、打款备注说明。
- **底部**：本次实结金额、已选 N/M 条明细；存在扣减时显示「明细合计 ¥X · 扣减待追回 ¥Y」。
- **二次确认**：点击「确认结算并同步」弹出弹窗，展示已选明细条数、明细合计、扣减退款待追回、本次实结及同步说明；确认后生成结算单并提示「结算成功：N 条明细，实结 ¥X（已扣减退款待追回 ¥Y），已同步合伙人端」，取消返回抽屉。

### 11.3 结算历史

- **列表字段**：结算单号（录入时已发放附「录入时已发放」徽标）、合伙人姓名、手机号、渠道徽标、结算金额（-¥X）、财务打款凭证号、经办人、核销时间、打款备注、操作。
- **操作**：「查看明细」打开结算明细抽屉；「合伙人详情」跳转该合伙人档案的「线下结算历史」Tab。
- **结算明细抽屉**：头部展示结算明细 · 结算单号、合伙人、核销时间、凭证号；表格列出 来源订单（类型徽标 + 订单号 + 来源）、期次、解冻日、结算金额，末行合计。

## 12. 系统设置

为运营后台的全局参数配置页，仅管理员可见；配置保存后对全系统所有管理者同步生效。

- **编辑方式**：配置项默认只读展示，点击对应卡片右上角「修改」后该卡片进入可编辑态，并出现「保存 / 取消」；取消恢复为上次保存值，卡片间互不影响。
- **保存确认**：点击「保存」弹出确认弹窗，逐条列出变更内容（原值 → 新值），确认后才写入生效；未发生变更时直接退出编辑态并提示。
- **配置生效**：仅作用于保存后的新数据与新计算，已有合伙人比例、已解冻 / 已结算部分不回溯。

### 12.1 默认分成比例

- **配置项**：内部渠道首购 / 续购比例、外部渠道首购 / 续购比例，共 4 项（取值 0~100 的整数，不支持小数）。
- **生效范围**：保存后同步为全系统所有管理者在申请审核通过、合伙人建档时带出的默认比例。
- **生效时点**：仅对保存后新审核 / 新建的合伙人生效，已有合伙人比例保持不变。

### 12.2 冻结规则

- **配置项**：防退款观察期天数 N，默认 7 天，可配置 0 ~ 60 天。
- **计算口径**：推广币解冻日 = 服务期结束日 + N 天；月卡 / 加油包整单一次性解冻，年卡与机构订单按期逐月解冻。
- **时间口径**：按 Asia/Shanghai 自然日计算，解冻时点统一为解冻日 **00:00:00**，当日即计入「可结算」；结算截止判断用 **23:59:59**。界面只展示日期，系统内部按时间点判定是否已解冻。
- **示例（N = 7 天）**：
  - 月卡：支付成功 `2026-03-15 14:22:37`，服务期 `2026-03-15 00:00:00 ~ 2026-04-14 23:59:59`，观察期 `2026-04-15 00:00:00 ~ 2026-04-21 23:59:59`，佣金于 **`2026-04-22 00:00:00`** 整单解冻并转入「可结算」。
  - 年卡：同一笔支付，第 1 期解冻 **`2026-04-22 00:00:00`**，第 2 期 **`2026-05-22 00:00:00`**，以此类推，第 12 期 **`2027-03-22 00:00:00`**，每期独立解冻。
  - 月末进位：`2026-01-31` 支付、N=7，第 1 期按 `2026-02-28 00:00:00` 服务期结束计算，解冻 **`2026-03-07 00:00:00`**；闰年 2 月按 2 月 29 日计。
  - N=0：服务期结束次日 `00:00:00` 立即解冻（如服务期至 `2026-04-14 23:59:59`，则 `2026-04-15 00:00:00` 解冻）。
  - 退款判定：退款时间早于解冻时点的期次按未解冻处理，等于或晚于解冻时点的按已解冻处理。
- **生效范围**：保存后全系统按新规则重算解冻日，并同步更新合伙人「可结算 / 冻结中」金额；已解冻、已结算部分不回溯。

### 12.3 运营账号管理

- **账号创建**：由超级管理员在后台新增，字段包含登录账号、姓名、角色、初始密码、账号状态。
- **账号规则**：格式与密码规则见 3.2；全局唯一，创建后不可修改。
- **角色权限**：
  - 超级管理员：全部菜单 + 运营账号管理；
  - 审核：申请审核、合伙人档案；
  - 财务：结算管理、订单与退款登记。
- **密码规则**：见 3.2；不提供自助找回，遗忘时由超级管理员重置。
- **停用**：停用后立即无法登录，已登录会话强制退出；停用不删除历史操作记录。
- **登录日志**：记录登录时间、IP、账号、结果（成功 / 失败），保留不少于 180 天。
