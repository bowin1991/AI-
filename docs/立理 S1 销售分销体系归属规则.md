# 立理 S1 销售分销体系归属规则

## 一、基本原则

分销体系采用「客户关系可重叠、订单业绩唯一归属」的原则。

- **客户归属：** 记录客户通过哪些销售渠道注册或转化，同一客户可以同时存在于多位销售的客户列表中。
- **订单归属：** 记录每笔订单对应的销售，每笔订单只能归属一位销售。


每位销售拥有专属推广链接和专属推广码，分别用于客户来源绑定和订单转化归属。

## 二、推广渠道与客户绑定规则

### 2.1 专属推广链接

1. 每位销售拥有唯一的专属推广链接。
2. 用户通过销售专属链接首次注册立理 S1 账号，系统自动建立用户与该销售的客户绑定关系，并将该用户加入销售的「我的客户」列表。该绑定关系长期保留。
3. 自用户注册成功之日起7天内，用户下单时，系统自动填入该销售的专属推广码，订单自动归属该销售，用户无需手动填写。
4. 超过7天后，客户绑定关系仍然保留，但系统不再自动填入原销售的推广码。此后用户下单，如需归属某位销售，需主动填写对应的专属推广码。
5. 用户此前已注册 S1 账号，通过其他销售的专属链接再次访问或登录，不建立新的绑定关系，也不改变原有客户来源记录。

### 2.2 专属推广码

1. 每位销售拥有唯一的专属推广码。
2. 用户在订单支付前主动填写有效推广码，经系统验证后，该笔订单归属推广码对应的销售。
3. 推广码具有订单归属优先权，不受用户是否已与其他销售建立客户绑定关系、是否处于7天自动填码期限内的影响。
4. 用户通过推广码成功产生付费订单后，自动进入对应销售的「我的客户」列表。
5. 用户首次成功填写有效推广码，可额外获得2000积分。同一用户仅享受一次该奖励。

## 三、客户归属规则

### 3.1 客户进入销售客户列表的条件

满足以下任一条件，客户即可进入对应销售的「我的客户」列表：

- **链接注册：** 用户通过该销售的专属推广链接首次注册成功。
- **推广码转化：** 用户使用该销售的专属推广码成功产生付费订单。

### 3.2 客户关系管理原则

1. 同一客户可以同时存在于多位销售的「我的客户」列表中。
2. 客户通过某位销售的推广码产生订单后，自动进入该销售的客户列表，不影响其在其他销售客户列表中的原有记录。
3. 客户不会因后续通过其他销售的推广码下单，而从原销售的客户列表中移除。
4. 客户来源绑定记录与推广码转化记录分别保留，不因订单归属变化而覆盖或删除。
5. 客户在不同销售客户列表中的重复出现，不代表客户数量或销售业绩可以重复计算。

## 四、订单归属与销售分成规则

每笔订单按照以下优先级确定唯一的销售归属。

### 4.1 第一优先级：专属推广码

1. 用户在订单支付前填写有效的销售推广码，该笔订单归属于推广码对应的销售。
2. 此规则优先于客户原有绑定关系。即使客户此前已通过其他销售的专属链接注册，仍以本次填写的推广码为准。

### 4.2 第二优先级：自动填入推广码

用户通过某位销售的专属链接首次注册后7天内下单，且未主动填写其他销售的推广码，系统自动填入原绑定销售的专属推广码，订单归属于该销售。

### 4.3 无销售归属

符合以下任一情况，且未主动填写有效推广码的订单，不归属于任何销售：

- 用户未通过销售专属链接注册。
- 用户通过销售专属链接注册，但已超过7天自动填码期限。
- 用户此前已注册，仅通过其他销售的专属链接再次访问或登录，未建立新的绑定关系，且不存在有效的原自动填码规则。

### 4.4 订单归属认定

1. 订单归属以支付前最终有效的推广码为准；未填写推广码时，依据7天自动填码规则判断。
2. 以订单支付成功时间作为销售业绩认定时间。
3. 订单支付成功后，分成归属锁定，不允许通过补填或修改推广码追溯变更已完成订单的归属。
4. 每笔订单只能归属一位销售，不允许重复计算销售分成。

## 五、销售后台数据归属规则

销售系统设置两个独立入口：「我的客户」和「我的订单」。

### 5.1 我的客户

展示满足以下任一条件的客户：

- 通过该销售专属链接首次注册的客户。
- 使用该销售专属推广码成功产生付费订单的客户。

客户满足任一条件即可进入对应销售的客户列表。进入后保留原有记录，不因后续通过其他销售渠道产生订单而移除。

可以查看的用户信息：手机号码（隐去中间4位）、注册时间、当前会员状态、会员等级、会员到期时间

### 5.2 我的订单

展示所有归属于该销售的订单，包括：

- 通过该销售专属推广码产生的订单。
- 通过该销售专属链接注册，并在7天内自动填入推广码产生的订单。

订单按照唯一归属原则计入对应销售的订单列表及销售业绩。

### 5.3 客户与订单的关系

1. 客户进入销售的客户列表，不代表该客户的所有订单都归属于该销售。
2. 销售的订单列表中出现某客户的订单，该客户也应自动进入该销售的客户列表。
3. 同一客户可以出现在多个销售的客户列表中，但同一笔订单只能出现在一位销售的订单列表中。

## 六、典型业务场景

假设销售 A 和销售 B 分别向客户 C 推荐立理 S1：

| 客户行为                  | A 的客户列表 | B 的客户列表 | 订单分成归属           |
| --------------------- | ------- | ------- | ---------------- |
| C 通过 A 的链接首次注册        | 有       | 无       | —                |
| C 通过 B 的链接再次登录        | 有       | 无       | —                |
| C 在7天内未主动填写其他推广码，直接下单 | 有       | 无       | A（系统自动填入 A 的推广码） |
| C 在7天内主动填写 B 的推广码下单   | 有       | 有       | B                |
| C 超过7天后填写 B 的推广码下单    | 有       | 有       | B                |
| C 超过7天后未填写推广码直接下单     | 有       | 无       | 无销售归属            |
| C 后续填写 A 的推广码再次下单     | 有       | 有       | A                |

说明：

1. A 始终保留 C 的原始客户来源记录。
2. B 通过推广码促成 C 购买后，C 自动进入 B 的客户列表。
3. A、B 均可继续跟进 C，争取后续订单转化。
4. 每笔订单独立确定归属，不因客户历史绑定关系而永久锁定销售分成。

## 七、异常及补充规则

1. **订单退款：** 订单取消、退款或支付失败，不计入有效销售业绩；已发放的销售分成按照退款规则冲回。
2. **推广码奖励：** 同一用户首次成功填写有效推广码，仅发放一次2000积分奖励。
3. **推广码修改：** 支付成功前允许修改推广码，以最终有效推广码确定订单归属；支付成功后不允许修改。
4. **重复注册：** 对同一用户通过多个账号重复注册、重复获取推广奖励等行为，依据平台账号风控规则处理。

## 八、核心规则汇总

| 业务事项    | 规则                  |
| ------- | ------------------- |
| 首次客户来源  | 以首次通过专属链接注册的销售为准    |
| 客户绑定关系  | 注册成功后立即建立，长期保留      |
| 自动填码期限  | 注册成功后7天内            |
| 自动订单归属  | 7天内自动填入原绑定销售的推广码    |
| 推广码订单归属 | 推广码优先，归属填写推广码对应的销售  |
| 客户列表    | 同一客户可同时进入多位销售的客户列表  |
| 订单列表    | 仅展示归属于当前销售的订单       |
| 销售分成    | 每笔订单唯一归属，不重复计算      |
| 客户关系    | 不因其他销售促成订单而删除原有记录   |
| 用户推广奖励  | 首次成功填写有效推广码奖励2000积分 |

**核心原则：客户来源可以多元，销售跟进可以重叠，订单归属必须唯一。**
