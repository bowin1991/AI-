# 第一部分 · 合伙人

## 1. 产品范围

本期建设立理 S1 合伙人端 H5/Web，承载合伙人从申请入驻到推广币核算的完整链路。

- **功能范围**：双模式登录与密码找回；申请资料提交、审核状态查看；专属推广链接、推荐码与二维码海报；客户概览、客户列表、备注与标签；推广币概览、流水与线下结算记录；个人资料查询。
- **推广币结算范围**：个人月卡、年卡、加油包（可填推荐码，结算周期同月卡），以及运营后台手工录入的机构订单（按机构订单分期规则计算）。
- **升级补差**：升级前原订单按退款规则扣回未解冻推广币；升级后的新订单填写推荐码才计算并归属推广币，未填写则不计算、不建立归属。
- **依赖与边界**：归因、订单与支付数据由 S1 业务端提供；退款暂未接入接口，由运营后台手工登记并同步扣减推广币；申请审核、渠道及分成比例配置、账号状态管理、机构订单录入与核销由运营后台完成。本系统仅展示推广币核算与核销结果，不承接终端交易，不执行线下实际打款。

## 2. 申请入驻与准入流程

- **页面内容**：

  - *注：页面视觉风格与排版由 UI 设计确定，不强制要求展示顶部 Banner 大图。*

### 2.3 提交后即时反馈与二次访问机制

1. **即时提交反馈**：
   - 表单提交成功后，页面立即展示提交成功提示：“申请已成功提交！官方运营团队将在 3-5 个工作日内完成审核，请保持电话畅通。”提交申请时设置的登录密码一并保存。
   - 页面下方提供快捷按钮【前往登录页】。
   - 提交申请时由服务端按手机号校验是否已有申请记录；若已存在，不创建新申请，并提示“该手机号已有申请记录，请登录查看状态”。
2. **后续再次访问机制**：
   - 申请人关闭网页或后续再次访问系统时，可通过登录页使用密码或验证码登录查看申请状态；审核中或已拒绝的申请仅可查看状态，不开放推广中心等合伙人正式功能。
   - 同一手机号仅保留一条申请记录，申请人提交后不可再次提交或自行修改资料。已拒绝的申请不提供再次申请入口；如需调整申请资料，由运营人员在后台修改，手机号不可修改。

## 3. 身份认证与安全登录

### 3.1 登录页规范


- **登录凭证与模式**：支持 **Tab 双模式切换登录**，**默认选中【密码登录】Tab**：
  1. **密码登录（默认 Tab）**：输入“手机号 + 登录密码”，支持明文/密文小眼睛图标切换，适合常规办公登录。
  2. **验证码登录**：输入“手机号 + 短信验证码”，适合免密快速登录。
- **页面布局要素**：
  - 顶部：立理 S1 合伙人门户品牌标识与 Slogan。
  - Tab 切换器：【密码登录】（默认激活） / 【短信验证码登录】。
  - 主体表单项：
    - 手机号输入框：普通手机号输入框（不自动带入脱敏手机号，用户手动输入或通过浏览器明文表单自动填充）。
    - 凭证输入框：密码输入框（默认呈现，只填一次，带明暗文切换小眼睛）或 短信验证码框（含 60 秒倒计时按钮）。
    - **【忘记密码？】入口**：位于密码输入框下方右侧，点击跳转至重置密码页面。
    - 【登录系统】主操作按钮。
  - **核心申请入口保留**：登录框底部显眼位置提供专属按钮/链接：**【申请成为立理合伙人】**，未提交过申请的用户点击直接跳转至申请入驻页。

### 3.2 忘记密码与找回流程规范

```mermaid
flowchart TD
    A[登录页 点击【忘记密码？】] --> B[进入找回密码页]
    B --> C[输入: 手机号 + 获取短信验证码]
    C --> D{校验手机号是否属于已申请合伙人}
    D -- 否(未申请过) --> E[弹窗拦截: 该手机号尚未申请成为合伙人<br/>引导前往【申请入驻】]
    D -- 是(已有记录) --> F[验证码校验通过 -> 设置新密码 (只填一次，无确认)]
    F --> G[校验密码合规性: 8-20位含字母和数字]
    G --> H[点击【确认重置】 -> 服务端加密更新密码]
    H --> I[轻提示: 密码重置成功，请重新登录]
    I --> J[自动跳转回登录页<br/>默认选中【密码登录】Tab 供输入新密码]
```

1. **访问入口**：登录页密码输入框下方的【忘记密码？】链接。
2. **重置表单字段规范**：
   - **手机号码**：输入 11 位大陆有效手机号。
   - **短信验证码**：6 位纯数字验证码，60 秒防重发倒计时。
   - **新登录密码**：8-20 位字符，必须同时包含英文字母和数字；**只填一次，没有确认密码**；默认掩码隐藏，支持点击右侧小眼睛图标显示明文。
3. **准入与安全性校验**：
   - 申请人获取验证码或提交重置时，服务端先校验该手机号是否曾提交过合伙人申请。若不存在，直接拦截提示：“该手机号尚未申请成为立理合伙人，无法找回密码”。
   - 验证码必须与手机号严格绑定并在 5 分钟内有效，单次重置成功后立即作废。
4. **重置完成交互闭环**：
   - 重置成功后，页面弹出轻提示（Toast）：“密码重置成功，请使用新密码登录”。
   - 页面延时 1.5 秒自动重定向至登录页，默认切换至【密码登录】Tab，申请人直接输入新密码即可登录。

### 3.3 申请状态查询与登录准入规则

用户在登录页使用“密码”或“验证码”点击【登录系统】后，服务端进行统一凭据校验与准入判定：

1. **未填写过申请表单的用户**：
   - **完全禁止登录**。服务端鉴权拒绝并返回特定错误码。
   - 前端弹窗友好拦截提示：
     > “该手机号尚未申请成为立理合伙人，请先提交申请。”
   - 弹窗内置快捷按钮【立即申请】，点击直接跳转至申请表单页并将该手机号自动带入表单。
2. **密码校验与防暴力破解安全策略**：
   - 密码登录模式下，若手机号或密码错误，明确提示：“手机号或密码错误”。
   - 同一账号 15 分钟内连续输错密码达到 5 次，系统自动锁定该账号密码登录 15 分钟。
   - 锁定期间界面明确提示：“密码连续错误次数过多，请 15 分钟后再试，或通过【短信验证码登录】及【忘记密码】重置后登录”。
   - **错误计数清零机制**：锁定期间仍可正常使用【短信验证码登录】，也可通过【忘记密码】完成重置；凡通过验证码登录成功、忘记密码重置成功，或密码登录成功，历史密码错误失败计数均自动清零。
3. **已有申请记录的用户**：
   - 凭证验证通过后可查看申请状态及审核结果；处于审核中或已拒绝状态时，仅能访问申请状态页，不开放推广中心等合伙人正式功能。
   - 已拒绝的申请不可重复提交或由申请人修改；如运营侧后续将状态调整为已通过，申请人刷新状态或重新登录后进入推广中心。
4. **已被官方冻结的合伙人**：
   - 登录时阻断提示：“您的合伙人合作权限已被暂停，如有疑问请联系官方管理员”，禁止进入系统。

### 3.4 登录后状态分流与权限隔离（核心逻辑）

短信验证码或密码校验成功后，系统根据申请审核状态或合伙人账号状态渲染对应视图。审核中和已拒绝用户只获得申请状态查询权限；只有审核通过且账号正常的合伙人可以进入推广中心及各业务功能：

| 申请审核状态               |           是否可见正式功能界面           | 登录后呈现视图与操作权限                                                                                                                                      |
| :------------------- | :----------------------------: | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| **审核中**(`PENDING`)   | **完全不可见**(无推广物料/无海报/无客户列表/无账本) | **【审核状态页】**：- 展示申请人真实提交资料：申请姓名、所属机构、手机号码、提交时间。- 进度提示：“您的立理合伙人申请正在审核中，官方团队将尽快完成审核，请保持电话畅通并耐心等待。”（不写具体天数）。- 页面仅提供【刷新状态】与【退出登录】操作，导航栏完全隐藏/锁定。        |
| **已拒绝**(`REJECTED`)  | **完全不可见**(无推广物料/无海报/无客户列表/无账本) | **【审核结果页】**：- 展示申请人真实提交资料：申请姓名、所属机构、手机号码、提交时间，以及当前审核状态。- 仅提供【刷新状态】与【退出登录】操作，不提供修改资料或再次申请入口。- 如运营侧将申请状态改为 `APPROVED`，申请人刷新状态或重新登录后直接进入推广中心。 |
| **审核通过**(`APPROVED`) |        **进入正式系统**(全权限开放)       | **【推广中心】（默认进入页）**：- 登录后直接进入推广中心页面，正常使用专属推广短链、动态二维码海报下载、我的客户多维表格列表、推广币中心及我的资料。                                                                    |

## 4. 推广物料与获客中心

推广中心是合伙人开展业务的核心工具箱，。

### 4.0 页面结构

推广中心页面由「三张概览卡 + 一整行推广海报卡」组成：

1. **我的专属推荐码**：4 位数字大字展示，底部提供【复制推荐码】，右下角显示当前生效「首购 30% / 续购 20%」。
2. **专属推广链接**：短链文本单行截断展示，底部提供【复制链接】，右下角显示「长期有效」状态。
3. **累计收益（推广币）**：展示净累计总推广币（数值后带「推广币」单位），底部提供【账本明细】（跳转推广币页），右下角显示「按月核算」。
4. **官方专属推广海报**：横跨整行的独立卡片，左侧海报预览，底部提供【复制短链】【保存海报图片】与使用提示。


### 4.1 专属推广链接

- **链接格式**：`https://s1.liliai.cn/?ref={partner_code}` 或短链 `https://s1.liliai.cn/r/{partner_code}`。
- **页面展示**：以卡片形式展示，链接文本单行截断（完整链接可在复制后查看）；卡片底部提供【复制链接】按钮。
- **交互反馈**：点击后将链接写入剪贴板，并轻提示“复制成功，可发送给微信好友、学术交流群或粘贴至社媒简介中”。
- **客户绑定**：用户经专属链接**首次注册**账号时建立客户绑定并进入客户列表；7 天自动填码、推荐码优先等规则详见 4.2.1。

### 4.2 专属推荐码

- **推荐码形态**：**4 位纯数字**（如 `8866`、`6812`），全局唯一。
  - **号段生成过滤规则**：系统在生成 4 位随机推荐码号码池时，自动排除过滤不吉利或忌讳的数字组合（例如排除连续纯 4 如 `4444`、谐音忌讳如 `1414`、`7414`、纯叠字或负面谐音号码）。
- **展示形式**：以高对比度卡片大字展示，底部提供【复制推荐码】按钮，卡片右下角展示当前生效「首购 30% / 续购 20%」。
- **引导文案（可选展示，非必现）**：
  > “提示：朋友在立理 S1 官网下单购买月卡/年卡/加油包时，在结算页输入您的专属推荐码，该笔订单即归属您并计算推广币收益。”

### 4.2.1 推荐码归因与 7 天带入规则

**基本原则**：客户关系可重叠、订单业绩唯一归属。客户来源可多元，合伙人跟进可重叠，订单归属必须唯一；销售分成以订单归属为准，不以客户绑定关系作为永久分成依据。

| 场景 | 系统行为 |
| :--- | :--- |
| 链接首次注册 | 用户通过合伙人专属链接**首次注册**账号，建立客户绑定并进入该合伙人客户列表，绑定长期保留；自注册成功起 **7 天内**下单，系统自动带入该合伙人推荐码，订单归属该合伙人 |
| 已注册用户再次访问 | 通过其他合伙人链接再次访问或登录，**不建立新绑定、不改变客户来源** |
| 主动填写推荐码 | 支付前填写有效推荐码，该单归属该推荐码对应合伙人，**优先于**客户绑定关系与 7 天自动带入 |
| 超过 7 天 | 客户绑定保留，但不再自动带入；下单需主动填写推荐码才产生归属 |
| 未填写且无法自动带入 | 未通过专属链接注册、已超 7 天且未填码、或已注册用户仅经其他合伙人链接再次访问且无自动填码规则，订单**不归属任何合伙人** |
| 支付后锁定 | 支付成功即锁定归属，不可补填或修改；支付前允许多次修改，以最终有效推荐码为准 |

- **客户列表进入条件**（满足任一即可）：① 通过该合伙人专属链接首次注册；② 使用该合伙人推荐码成功产生付费订单。
- **客户记录保留**：满足条件后长期保留，不因客户后续通过其他合伙人下单而移除；同一客户可同时出现在多个合伙人的客户列表，但同一订单只归属一位合伙人。重复出现不重复计算订单与业绩。
- **来源与成交记录分离**：客户来源绑定记录与推荐码成交记录分别留存，不因订单归属变化而覆盖或删除。
- **业绩认定时间**：以订单**支付成功时间**认定业绩；支付成功前允许多次修改推荐码，支付成功后锁定，不可补填或追溯更改。
- **推广奖励**：用户首次成功填写有效推荐码，用户额外获得 2000 积分，具体发放金额待定。
- **退款**：退款或支付失败的订单不计入业绩，已产生的推广币按退款规则冲回。
- **风控**：同一用户重复注册、重复获取推荐码奖励等行为，按平台账号风控规则处理。

**示例**：客户 C 首次通过 A 的专属链接注册，进入 A 的客户列表；注册后 7 天内直接下单，系统自动带入 A 的推荐码，订单归 A。期间 C 主动填写 B 的推荐码下单，该单归 B，C 同时进入 B 的客户列表，A 处的客户记录保留。注册满 7 天后未填写推荐码下单，该单无销售归属。

> 完整业务口径（含全场景对照表）以《立理 S1 销售分销体系归属规则》为准，本节为其在合伙人端需求中的落地描述。

## 6. 推广币与账务中心

### 6.1 推广币属性合规隔离原则

> \[!IMPORTANT]
> **合规红线**：
>
> 1. 合伙人端界面**全站严禁出现“1推广币=1元”、“可兑换现金X元”、“现金钱包”等字样**，规避金融监管与无牌支付风险。
> 2. 推广币作为合伙人推广贡献度的统一计量单位。具体的结算政策由官方运营在入驻协议或线下沟通中约定。

### 6.2 核心指标看板

看板全面升级为四大核心指标卡（彻底取消原“月末可解冻推广币”指标），清晰展示合伙人收益全貌：

```
+---------------------------------------------------------------------------------+
|     总推广币              可结算推广币            冻结推广币            已结算推广币       |
|     12,680                 4,000                3,680                5,000      |
+---------------------------------------------------------------------------------+
```

1. **总推广币**：自合伙人入驻以来的**净累计总推广币**。
   - **计算口径**：$\text{总推广币} = \text{累计获得推广币} - \text{退款扣除推广币} = \text{可结算推广币} + \text{冻结推广币} + \text{已结算推广币}$
   - **业务特征**：总推广币代表合伙人净累计推广成果，**不会因为线下结算打款核销而减少**；发生退款扣除时，总推广币相应净减少。
   - **卡片表现**：卡片标题为「总推广币 (净收益)」，底部附注「可结算+冻结+已结算」。
2. **可结算推广币**：已完全度过防退款观察期（套餐周期结束 + T+N 天，N 默认 7 天、可在系统设置中配置）、目前可供官方财务进行线下打款核销的推广币余额。
3. **冻结推广币**：尚处于防退款观察期内的推广币。此部分推广币暂时不可用于结算，若遇退款将直接扣除。
   - **卡片表现**：卡片底部附注「履约周期保护中」与「待退款保护期后解冻」。
4. **已结算推广币**：官方财务已在线下完成实际打款并已在后台核销同步的累计历史推广币数额。

> \[!NOTE]
> 页面不提供自助【申请结算】入口；线下打款由官方按月统一处理，并在运营后台核销后回传至本页。

### 6.3 推广币发放与解冻规则（月卡 / 年卡 / 加油包）

推广币生命周期为三步：**产生（发放）→ 冻结（防退款观察）→ 解冻（进入可结算）**。推广币产生后一律先计入「冻结推广币」，只有到达解冻日才转入「可结算推广币」。

#### 6.3.1 发放（产生）时点

- 终端用户**支付成功**即产生推广币，金额 = 订单实付 × **该单适用分成比例**，由服务端四舍五入**保留 2 位小数（精确到分）**，全部推广币数值（订单总额、分期金额、账户汇总、流水与结算）统一按两位小数展示；订单卡片上的「本单有效推广币」即该订单产生的总推广币，卡片「记账时间」即支付成功时刻。
- **首购与续购界定**：首购指该客户在立理 S1 平台的**首笔成功付费订单**，适用首购比例；该客户的其余订单（复购、续费、升级补差）均适用续购比例。比例在订单支付成功时锁定，不随合伙人后续比例调整追溯变化。
- 支付时点同时作为分期解冻日的计算基准（下文以「支付成功日」表述）。

#### 6.3.2 月卡 / 加油包：一期制，整单一次性解冻

> 加油包下单同样支持填写推荐码，推广币结算周期与月卡一致，按本节规则执行。

| 项目 | 规则 |
| :--- | :--- |
| 发放方式 | 支付成功时一次性产生全额推广币，不分期 |
| 期数 | 1 期 |
| 解冻日 | **支付成功日 + 1 个月 + N 天**（即月卡服务期结束后再叠加 T+N 天防退款观察期，N 默认 7 天） |
| 状态流转 | 未到解冻日：`冻结中` → 解冻日当天（含）起：`已解冻`（整笔推广币转入可结算） |
| 示例 | 月卡实付 ¥369.00 × 30% = 110.70 → 产生 `110.70` 推广币；支付日 2026-11-03 → 解冻日 **2026-12-10**，当日 110.70 推广币全部转入可结算 |

#### 6.3.3 年卡：12 期分期，逐月解冻

| 项目 | 规则 |
| :--- | :--- |
| 发放方式 | 支付成功时一次性产生订单总推广币，再按 12 期拆分展示与解冻 |
| 期数 | 12 期 |
| 分期金额 | 按「分」均分，保留 2 位小数：前 11 期 = `round(总额 / 12)`（四舍五入到分），第 12 期 = 总额 − 前 11 期之和（尾差归入最后一期，保证 12 期合计等于总推广币） |
| 解冻日 | 第 k 期解冻日 = **支付成功日 + k 个月 + N 天**（k = 1…12），即每个服务月结束后再叠加 T+N 天 |
| 状态流转 | `分期解冻中 n/12`（n 为已解冻期数）→ 第 12 期解冻后为 `已全部解冻` |
| 示例 | 年卡实付 ¥2,999.00 × 30% = 899.70 → 总推广币 `899.70`；每期 899.70 ÷ 12 = 74.975 → 前 11 期各 `74.98`，第 12 期 `899.70 − 74.98×11 = 74.92`；支付日 2026-11-03 → 第 1 期 2026-12-10 解冻 74.98、第 2 期 2027-01-10 解冻 74.98……第 12 期 2027-11-10 解冻 74.92 |

- **期次展示**：订单卡内以 12 段色块进度条呈现（绿色=已解冻、黄色=冻结中、红色=退款扣除），并附「已解冻 n/12 期 · 下期 YYYY-MM-DD 解冻 +X」摘要；点击【查看分期明细】逐期展开「第 n 期 / 解冻日 / +X / 状态」。
- **解冻判定口径**：解冻日当天（含）即视为已解冻，由服务端按自然日计算（`加月 + N 天`，遇月末按目标月末自然截断）。

#### 6.3.4 退款对发放与解冻的影响

1. **扣回金额重算**：退款后按净实付重新结算，`应扣回推广币 = round2(原实付 × 该单适用分成比例) − round2((原实付 − 退款金额) × 该单适用分成比例)`（round2 为四舍五入保留两位小数）；全额退款时本单有效推广币归零。
2. **扣回顺序**：只扣退款发生时**尚未解冻**的期次，且**从最后一期往前倒扣**；已经解冻并进入可结算的期次不回滚、不扣减。
3. **展示表现**：
   - 期次被扣空 → 该期标记 `退款扣除`，金额显示 `−X`（并附「（原 X）」）；
   - 部分退款 → 订单徽标追加 `部分退款`，卡片展示红色退款信息行「部分退款 ¥X（日期）· 扣除 −X 推广币」，右侧「本单有效推广币」取退款后净值，并以删除线展示原总推广币；
   - 全额退款 → 订单徽标直接变为 `已全额退款`，全部分期标记 `退款扣除`。
4. **示例（部分退款）**：年卡实付 ¥2,999.00，2026-08-20 支付，分成比例 30%，总推广币 899.70，12 期（前 11 期 74.98、第 12 期 74.92），每期服务金额 249.92（第 12 期 249.88）。
   - 2026-11-06 客户申请退款：第 3 期服务期（2026-10-20 ~ 2026-11-19）已使用一半，按半退；第 4 期起（2026-11-20 之后）未使用，全额退。
   - 退款金额 = 第 3 期一半 124.96 + 第 4~12 期 2,249.24 = **¥2,374.20**，退款后净实付 624.80。
   - 应扣回 = `2,999 × 30% − 624.80 × 30%` = 899.70 − 187.44 = **712.26**。
   - 扣回顺序从最后一期往前：第 12 期 74.92、第 11~4 期各 74.98（共 599.84）全部扣空，第 3 期再扣 37.50、余 37.48 继续冻结（对应已使用的半个服务月，2026-11-27 解冻）；第 1~2 期已于 2026-09-27、2026-10-27 解冻，共 149.96 不回滚。
   - 结果：本单有效推广币 187.44，该合伙人待追回金额为 0（冻结期次足以抵扣）。

#### 6.3.5 升级补差订单

1. **升级前原订单**：按 6.3.4 退款规则处理，即按净实付重算推广币，从最后一期往前扣回尚未解冻的期次；已解冻部分不回滚。
2. **升级后新订单**：填写了推荐码的，按新订单实付 × 续购比例正常产生推广币并归属该推荐码对应合伙人，解冻规则按新套餐类型执行；未填写推荐码的，不产生推广币、不建立归属，仅记录订单。
3. **展示表现**：原订单标注 `升级补差（原单扣回）`，新订单按普通订单展示推广币与分期。

#### 6.3.6 解冻后如何进入结算

- 解冻只做「冻结 → 可结算」的账户级转换，不按订单单独打款；
- 官方财务按月对账户整体核销线下打款（金额从可结算转入已结算），核销记录见 6.5 节；
- 订单维度仅承担「推广币产生 + 分期解冻 + 退款扣回」核算，不体现打款动作。

> \[!NOTE]
> 上述解冻与扣回均由服务端定时任务（按天跑批）执行并回传前端，前端只做展示，不参与计算与状态判定。

运营后台为合伙人体系的运营与财务中枢，包含申请审核、合伙人管理、订单管理、结算管理四个模块。侧边栏「管理后台」分组自上而下依次为：申请审核（实时显示待审核数量角标）、合伙人管理、订单管理、结算管理；顶栏提供全局搜索与「系统默认分成比例」配置入口。

## 8. 申请审核

负责合伙人入驻申请的状态流转与准入建档，默认进入「待审核」列表。

### 8.1 筛选与列表

- **分段 Tab**：待审核（默认）、已通过、已拒绝、全部申请，Tab 不显示数量；侧边栏菜单不显示待办数量提醒。
- **筛选条件**：关键词（申请 ID / 姓名 / 完整手机号 / 机构单位，输入即实时过滤）、审核状态、申请时间区间（日历选择起止日期，支持「近 7 天」「本月」快捷预设与清空）。
- **列表字段**：申请人姓名、手机号、所属单位 / 学术机构、微信号、申请时间、审核状态、操作。列表不展示申请编号与身份属性。
- **按 Tab 差异展示**：
  - 待审核：申请时间之后直接为审核状态，不展示操作人与处理时间。
  - 已通过：在申请时间后增加「入驻时间」（即审核通过时间），并在审核状态后增加「操作人」（执行通过的运营账号）。
  - 已拒绝：在申请时间后增加「拒绝时间」，并在审核状态后增加「操作人」（执行拒绝的运营账号）。
  - 全部申请：展示「操作人」列，已通过 / 已拒绝显示对应审核人，待审核留空。
- **排序规则**：仅按时间排序，支持「最新优先 / 最早优先」切换。待审核默认最早优先（先到先审）；已通过按入驻时间、已拒绝按拒绝时间、全部申请按申请时间，默认最新优先。切换 Tab 或变更筛选条件后恢复该 Tab 的默认排序。

### 8.2 审核操作

| 操作 | 交互与校验 | 结果 |
| :--- | :--- | :--- |
| 详情 | 抽屉展示申请资料与操作日志 | 只读查看 |
| 通过 | 弹窗选择渠道类型（外部 / 内部，默认外部）、填写首购与续购比例、填写专属推荐码 | 自动在合伙人管理建档并激活账号 |

| 拒绝 | 无需填写拒绝原因，确认后直接拒绝 | 申请人状态页显示已拒绝，不展示原因 |

- **首购 / 续购比例**：各取值 0.0% ~ 100.0%，允许一位小数；按渠道类型自动带出系统默认值（内部 首购 15.0% / 续购 10.0%，外部 首购 30.0% / 续购 20.0%，可在「系统设置」中调整），仅对后续新订单生效。

- 默认分成比例统一在「系统设置」维护（见 12），不在此页配置。
- 所有审核动作写入申请记录的操作日志（时间、经办人、动作、说明）。

### 9.3 账号操作规范

| 操作 | 必填项 | 业务影响 |
| :--- | :--- | :--- |
| 修改分成比例 | 新首购比例、新续购比例（0-100%，一位小数）、修改原因 | 仅对修改后新产生订单生效，历史订单不追溯重算 |

订单管理为运营后台独立模块，承载用户订单与机构订单的全量台账；页面内以分段 Tab 切换「用户订单」「机构订单」，列表操作可下钻分期明细或登记退款。

### 10.1 用户订单

- **数据来源**：S1 业务端线上订单（月卡、年卡、加油包、升级补差），系统自动归集，无需人工录入。
- **筛选条件**：关键词（订单编号、客户手机号、合伙人姓名、推荐码、套餐名，模糊匹配）、订单状态（全部 / 已支付 / 已退款）、套餐类型（全部 / 月卡 / 年卡 / 加油包 / 升级补差）；汇总条与列表均按筛选结果统计。
- **汇总条**：订单总数、总销售金额（订单实付合计扣除已登记退款）、佣金合计（扣除退款冲回），均按筛选结果实时统计。
- **列表字段**：订单编号、下单客户手机号、商品 / 套餐、归属合伙人（内部 / 外部渠道）、订单状态、订单金额、该单适用分成比例、本单佣金、下单时间、操作。
- **展示规则**：
  - 商品列展示两行：主行为套餐名（Lite / Pro / Max 月卡、年卡、加油包）；次行为单笔类型标签：`首购` / `续购` / `升级补差` / `机构`，四者互斥。
  - 首购指该客户在平台的首笔成功付费订单，其余订单标注续购；升级补差订单标注「升级补差」不重复标注续购；机构订单标注「机构」。
  - 本单佣金正数显示 `+¥X`；发生退款后按退款后实付金额重算，最低为 0，不显示负数，并在下方注明「原 +¥X · 扣回 ¥X」。
  - 订单状态仅两种：`已支付`（无退款记录）、`已退款`（存在退款登记），状态列不再附加退款金额说明；退款金额与扣回明细在分期明细中查看。已退款订单仍可查看分期明细，对应期次标记为退款扣除。
  - 解冻进度与可结算 / 冻结中 / 已结算金额不在本列表展示，统一在分期明细与结算管理中查看。
- **操作**：`分期明细`（弹窗顶部展示订单金额、分成比例、本单佣金；发生退款时追加退款金额、退款日期、原因、凭证与扣回金额，下方逐期展示期次、服务期间、解冻日、金额、状态）、`退款登记`（已全额退款的订单不再提供该入口）。订单页不提供结算入口，结算统一在结算管理处理。


### 10.2 机构订单

- **业务背景**：机构年度套餐为线下签合同，无法在线上自动打通，由运营手动录入。
- **列表字段**：合同编号、机构名称、商品名称（含服务期月数）、合伙人、订单状态、订单金额、分成比例、本单佣金、下单时间、操作；订单状态与用户订单一致，仅「已支付 / 已退款」两种。
- **编号口径**：
  - **合同编号**：录入时按线下纸质合同手工填写，作为财务对账凭证锚点，系统内唯一（重复录入时拦截并提示）。
  - **系统订单号**：录入后自动生成 `ORG-YYYYMMDD-序号`（服务起始日 + 三位流水号）；佣金分期以「系统订单号 # 期次」为唯一键。
- **服务周期**：按合同展示起始日 ~ 结束日及总月数；解冻规则与年卡一致，逐月分期，每期在服务月结束 +N 天后解冻。
- **操作**：`分期明细`；不提供结算入口。
- 页面右上角提供「录入机构订单」。

### 10.3 录入机构订单

| 字段 | 必填性 | 规则说明 |
| :--- | :---: | :--- |
| 归属合伙人 | 必填 | 默认带出该合伙人续购比例 |
| 机构名称 | 必填 | 线下签约机构全称 |
| 合同编号 | 必填 | 手工填写，系统查重 |
| 合同金额（元） | 必填 | 按合同实际金额 |
| 分成比例（%） | 必填 | 可按合同调整；**录入后锁定**，不随后续比例调整变化 |
| 服务起始日 | 必填 | 决定分期与解冻基准日 |
| 服务周期（月） | 必填 | 1-60 个月 |
| 已发放金额（元） | 选填 | 录入前已线下发放的佣金，按期次从前往后抵扣 |
| 备注 | 选填 | 合同补充说明 |

- **分期预览**：填写过程中实时展示应分佣金总额、已发放、可结算、冻结中，并逐期预览「期次 / 服务期间 / 解冻日 / 金额 / 状态」。
- **已发放金额处理**：抵扣后生成一条「录入时已发放」的结算记录，该记录不可撤销。
- **提交后**：生成机构订单及分期明细，写入合伙人积分与流水，页面自动切换至「机构订单」列表。

### 10.4 与结算管理的衔接

- 结算管理仅保留「待结算」「结算历史」两个 Tab，机构订单台账不再内嵌其中。
- 机构订单解冻后的明细与其他来源一致，统一进入「待结算」按合伙人核对结算。
- 结算历史支持穿透至「合伙人详情」（详见 11.4）。

### 10.5 退款登记（无接口，运营手工登记）

**背景**：系统暂未接入退款接口，实际退款须由运营手工登记，合伙人佣金才会同步扣回。

**入口与范围**
- 用户订单、机构订单列表行内「退款登记」均可发起；已退满（累计退款 = 实付）的订单不再提供入口。
- 同一订单可多次登记部分退款；已登记内容不支持修改，需「撤销全部退款登记」后重新登记。

**表单字段**

| 字段 | 必填 | 规则 |
| :--- | :---: | :--- |
| 退款金额（元） | 是 | ≤ 实付 − 累计退款 |
| 退款日期 | 是 | ≤ 当天 |
| 退款原因 | 是 | 文本 |
| 退款凭证号 | 否 | 财务退款流水号 / 商户退款单号 |

**扣回规则**
- 应扣回佣金 = `round2(实付 × 该单适用分成比例) − round2((实付 − 累计退款) × 该单适用分成比例)`（round2 为四舍五入保留两位小数）。
- 从最后一期往前，逐期扣回尚未解冻的期次；已解冻、已结算期次不扣。
- 无法扣回的差额计入该合伙人「待追回金额」，在下次结算打款时扣减。

**实时预览**：展示应扣回佣金、可扣回期次（逐期扣回金额）、计入待追回金额、退款后本单佣金。

**提交后联动**
- 订单：标记「部分退款 / 全额退款」，分成金额显示净额（附原值与扣回额），解冻进度重算，被扣空期次显示「退款扣除」。
- 合伙人：总佣金减少，可结算 / 冻结中 / 已结算与待追回金额同步重算。
- 留痕：写入合伙人流水「退款扣除」与操作日志（经办人、退款金额、扣回额、凭证），合伙人端佣金同步扣减。

**撤销**：支持撤销该订单全部退款登记，佣金、可结算金额与待追回金额同步回滚，并记录操作日志。

## 11. 结算管理

### 11.1 结算依据

- 以「已解冻、尚未结算的佣金明细」为单位结算，按合伙人整体核销，不按订单单独打款。
- 结算周期按自然月：每月仅结算**上月最后一日（含）之前解冻**的明细，当月及之后解冻的顺延至下期。
- 明细来源：线上月卡 / 年卡 / 加油包 / 升级补差订单、机构订单；每期在服务月结束 +N 天后解冻，解冻后计入合伙人「可结算」。

### 11.2 待结算

- **汇总**：有可结算明细的合伙人数、待打款合计，并拆分「线上套餐 / 机构订单」金额。
- **列表字段**：合伙人 / 单位（含手机号）、渠道、账号状态、可结算构成（线上套餐金额 / 机构订单金额 + 订单数 + 期明细数）、可结算金额、最早解冻日、操作。
- **结算方式**：逐位合伙人点击「核对并结算」进入核对单；不提供批量勾选与批量导出。
- **账号限制**：已冻结合伙人操作列显示「不可结算」，需先在合伙人档案解冻。

### 11.3 结算核对（核销闭环）

- **弹窗内容**：合伙人信息（姓名 / 渠道 / 单位 / 手机号 / 微信）、本期可结算范围提示、可结算明细表；不展示结算依据说明段，也不提供截止日选择。
- **结算范围**：系统固定按「上月最后一日（含）之前解冻」为可结算范围。例如 11 月结算仅可勾选 10 月 31 日及之前解冻的明细；11 月解冻的明细顺延至 12 月结算。
- **默认勾选**：进入弹窗时自动全选范围内全部明细，可手动取消或「全选 / 清空」。
- **明细表字段**：勾选、来源订单（类型徽标 + 订单号 + 来源）、客户 / 机构、期次 / 服务期间、解冻日、核验信息（实付、该单适用分成比例、本单总佣金）、本次可结算（已部分结算时附原金额提示）、明细状态（可结算 / 已部分结算）。
- **金额口径**：结算金额 = 范围内勾选明细的「本次可结算」合计，系统自动汇总，不可手填。
- **退款待追回扣减**：合伙人存在「待追回金额」时，按「待追回 ≤ 明细合计」自动扣减，本次实结 = 明细合计 − 扣减额；超出部分结转下次扣减，结算单同时记录明细合计与扣减额。
- **必填项**：财务打款凭证流水单号（系统自动生成、可修改）；选填项：结算经办人、打款备注。
- **确认后同步**：勾选明细标记为已结算并生成结算单（`SETTLE-年月-序号`）；同步写入合伙人流水「线下结算核销」、合伙人结算历史与操作日志，合伙人端可结算金额实时扣减。

### 11.4 结算历史

- **列表字段**：结算单号（录入时已发放的记录额外标识）、合伙人（姓名 + 手机号）、渠道、结算金额、结算内容（期明细数 + 来源标注）、财务打款凭证号、经办人、核销时间、打款备注、操作。
- **操作**：
  - `查看明细`：展开该结算单包含的期次明细；
  - `修改备注`：编辑打款备注；
  - `撤销结算`：回滚该结算单明细至未结算状态并恢复合伙人可结算金额，同时回退该结算单已扣减的退款待追回金额，并写入操作日志；「录入时已发放」的结算单不支持撤销；
  - `合伙人详情`：跳转该合伙人档案的「线下结算历史」Tab，用于账目溯源核对。
- 页面右上角提供「导出结算台账」。

## 12. 系统设置

为运营后台的全局参数配置页，仅管理员可见；配置保存后对全系统所有管理者同步生效。

- **编辑方式**：配置项默认只读展示，点击对应卡片右上角「修改」后该卡片进入可编辑态，并出现「保存 / 取消」；取消恢复为上次保存值，卡片间互不影响。
- **保存确认**：点击「保存」弹出确认弹窗，逐条列出变更内容（原值 → 新值），确认后才写入生效；未发生变更时直接退出编辑态并提示。
- **配置生效**：仅作用于保存后的新数据与新计算，已有合伙人比例、已解冻 / 已结算部分不回溯。

### 12.1 默认分成比例

- **配置项**：内部渠道首购 / 续购比例、外部渠道首购 / 续购比例，共 4 项（0.0% ~ 100.0%，允许一位小数）。
- **生效范围**：保存后同步为全系统所有管理者在申请审核通过、合伙人建档时带出的默认比例。
- **生效时点**：仅对保存后新审核 / 新建的合伙人生效，已有合伙人比例保持不变。

### 12.2 冻结规则

- **配置项**：防退款观察期天数 N，默认 7 天，可配置 0 ~ 60 天。
- **计算口径**：推广币解冻日 = 服务期结束日 + N 天；月卡 / 加油包整单一次性解冻，年卡与机构订单按期逐月解冻。
- **生效范围**：保存后全系统按新规则重算解冻日，并同步更新合伙人「可结算 / 冻结中」金额；已解冻、已结算部分不回溯。
